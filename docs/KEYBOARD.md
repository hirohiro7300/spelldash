# SpellDash専用キーボード 設計メモ（2026-09-16 実装。仕様は docs/APP.md §4）

> 2026-07-16 創業者指示で構想のみ。**2026-09-16 アプリ化の決定に伴い実装**（`js/keyboard.js`）。以下は当初の設計メモ。

## 目的

- 日本語切替不要（OSキーボードのIME切替がスペル入力の最大の摩擦）
- 数字・記号・予測変換不要 → 誤タップ削減
- 入力速度向上とUX統一（端末・OSによらず同じ配列・同じ打鍵感）

## 構成

**A〜Z + Backspace のみ。** それ以外のキーは置かない。

## 設計案（アプリ化後の検討たたき台）

- 配列: QWERTY基本（物理キーボード学習との一貫性を優先。ABC配列は採用しない）
- キーは3段配列＋最下段中央にBackspace幅広キー。Shift/スペース/Enterは不要
  - 開始・答え表示・パスなどの操作は画面側ボタンが担う（キーボードは文字入力専任）
- 打鍵フィードバック: 既存WebAudio SEと統一、触覚（Haptics）はアプリ化後のネイティブAPIで
- 正解プレフィックスのハイライトと連動して、次に打つべきキーを薄く光らせる補助モード（オプション、デフォルトOFF: 学習の邪魔をしない）
- はちゃんは置かない（1画面1目的・入力領域は聖域）

## 実装解禁の条件

1. アプリ化（ネイティブ or Capacitor等）が決定している
2. PMF探索フェーズを抜け、スマホ体験のボトルネックが「OSキーボード」だと定性フィードバックで確認できている

## 現Webでの代替（実装済みの範囲）

- inputイベント照合によるソフトキーボード対応（予測変換・一括挿入対応）
- `autocapitalize="off" autocorrect="off" spellcheck="false"` などの入力属性調整

## 現Webのキーボードショートカット（実装済み・2026-09-07）

| キー | 動作 |
|---|---|
| Enter | 開始 ／ 分からない（答え表示）／ 答え表示後はスキップして次へ ／ 正解後の待ちの間は次へ。次の語が出てから 0.3 秒の Enter は、その語にまだ打っていなければ答えを開かない。待ちが終わって次の語が出たときは、前の語を打ち終えてから 1.2 秒の Enter も同じ（打ち終えたら Enter で次へ、の癖を次の語の「分からない」にしない） |
| Esc | Enter と同じ「分からない」（プレイ中のみ。正解後の待ちの間は何もしない） |
| Ctrl+.（Cmd+.） | 今の単語を発音 |
| Tab | 次の要素へ（正解後の待ちの間は効かない） |
| 💡 ヒント（ボタン） | 7秒迷うと表示。次の1文字を見る（×扱い） |

## 日本語の答え: 読みをローマ字で（2026-10-08）

- 日本語の答え（鎌倉幕府・ファシズム・X線 など。かな・漢字を含む答え）は、漢字に変換せず**読みをローマ字で打つ**（`js/romaji.js`、`body.romaji-answer`）。打ったかなの下に打ったキーを小さく出す（2 段）。1 打ずつ判定し、読みを打ち終えたら Enter なしで正解
- 入力欄は**読み取り専用**（`readonly`）にする。IME も OS キーボードも開かず、keydown だけが届く。IME が打鍵を取った形（`key` が `Process`）や JIS かな配列（`key` がかな）でも、物理キーの位置（`code` の `KeyA`〜`KeyZ`・`Digit`・`Minus`）でローマ字にする
- 画面キーボード: A〜Z に **ー**（長音。`-` として送る）を足す。ローマ字のカードでは常に出す（ー がある語だけに出すと答えの手がかりになる）。入力欄が読み取り専用なので、タッチ端末では設定が「オフ」でも盤面を出す
- ⌫ は受理済みの文字を消さない（英単語と同じ 1 ミス＝不正解）。空白・記号・Backspace は判定しない（ミスにもしない）
- 綴り: ヘボン式・訓令式の両方（shi/si, chi/ti, tsu/tu, fu/hu, ji/zi, sha/sya, cha/tya/cya, ja/zya/jya …）、小さいかなは x／l、っ は子音を重ねる（xtu も可）、ん は nn／n'／子音の前の n／語末の n。ー は -。ぢ・づ・を は di・du・wo のほか ji・zu・o でも通る
- どの読みでも打ち終えた時点で正解（Enter は要らない。長い読みの手前の読みで終わることもある）。打ち終えた直後に、終えた語の読みの続き（語末の ん の 2 つ目の n、長い読みの残り）として打ったキーは次の語の打鍵にしない。仕組みと時間は英単語と共通（次の節の「打ち越し防止」: 正解後の待ちの間は飲み、続きを打つ間は次の語を待たせる。次の語が出た後は最後の打鍵から 0.6 秒の窓。Enter で自分から次へ進んだときは、次の語の 1 打目から受け付ける）。続きの窓の中では、次の語の頭と同じキーでも前の語の続きが先＝鑑真を n 1 つで終えた直後の n は 日米和親条約 の に にしない。ただし続けて打った i が に に続かず、n＋i なら続くときは、飲んだ n を次の語に戻す（速い人が次の語を打ち始めていた）
- かなの読み（accept のかな）が 1 つもないカード（自分で作った場面カードなど）は従来どおり入力欄に IME で打って Enter
- 読みの続きの持ち越し止めは、英単語の打ち越し防止（次の節）と同じ仕組み・同じ窓（`js/game.js` の `spill`・`SPILL_GAP_MS` = 600ms）

## 英単語: 出題語が別の正解の先頭部分のとき（2026-10-10、K0-1）

- **出題語を打ち切ったらその場で正解**（gym に対して gymnasium、a に対して an、sport に対して sports、photo に対して photograph が候補に残っていても止めない。`js/answers.js completedAnswer`）。以前は「まだ伸びる候補がある」として止め、Enter で答えが開いて×（思い出せず）になっていた（全パック有効で 170 枚）。出題語より短い別解（出題語 advertisement に対して ad・advert）は今までどおり、打ち切っても止めず、Enter で別解として受ける
- **Enter は「打った語で確定」**: 答えを見る前で、打った綴りがそのまま候補の 1 つに一致しているなら、出題語でも別解でもその語で確定する（出題語なら正解、別解なら「X も…この問題の語は Y」）。一致していなければ今までどおり答えを表示（×）。答えを見た後・全文入力・ローマ字の Enter は変えない
- **英語の打ち越し防止**（ローマ字の読みの続きと同じ仕組み。`js/game.js` の `spill`）: 出題語で完成したとき、打った綴りより長い候補が残っていれば（a → an、gym → gymnasium、sport → sports）その続きの綴りを覚え、続きとして打ったキーは次の語の打鍵にしない。Study・Challenge・Daily とも。Shift など文字でないキーでは途切れさせない
  - **正解後の待ちの間**（Study）: 続きのキーは間が空いても続きとして飲む（このキーは次の語に入らない）。続きを打ち始めたら、打ち終えるか、最後の続きの打鍵から 1.5 秒（`SPILL_HOLD_MS`）手が止まるまで、タイマーで次の語を出さない（1 打 0.6 秒より遅い人・綴りを思い出しながら打つ人の続きが次の語に流れない）。待ちの間に続きを打ち切ったら、普通の待ち（設定「正解のあと」の長さ）を続きの最後の打鍵から数え直す（続きの直後の余分な 1 打＝空白・gymnasiums の s を、普通の語の後と同じだけ待ちの間に捨てる）。続きを打たない人の待ちは変わらない。Enter で自分から次へ進んだら捨てる
  - **次の語が出た後の窓**（最後の打鍵から 0.6 秒、`SPILL_GAP_MS`）: 次の語の頭と同じキーでも続きを先に見る（ローマ字と同じ）。窓が次の語に重なるのは、Study では次の語が出て「0.6 秒 − 待ち（0.25 秒〜）」、Challenge・Daily（待ちなし）では次の語が出て 0.6 秒まるごとで、続きを打つたびに延びる。速い人の次の語の 1 打目を飲むことがあるので、飲んだキー＋次のキーで次の語に続き、次のキーだけではミスになるときは、飲んだキーを次の語に戻す（a の直後の not の n、in の直後の six の s・i）
  - **窓の外**（最後の打鍵から 4 秒まで、`SPILL_LATE_MS`。綴りを思い出しながらの 2〜3 秒の迷いも入る）: 次の語の 1 打目がミスになるときだけ、そのキーが続きの次の字なら続きとして飲む（Challenge・Daily のゆっくりな続き、待ちの後に打ち始めた続き）。次の語の頭として通る字はそのまま次の語へ入れるが、それが続きの次の字でもあれば続きとしての見方も残す（`spillLent`）。次のキーで次の語がミスになり、続きには続くなら、次の語に入れた字を外して続きとして飲む（1 打 0.9 秒の gymnasium の s と次の語 subject の頭、u と uniform の頭）。続きがその字で終わっていて、いまのキーが次の語の 1 打目として通るなら、入れた字を外していまのキーを 1 打目にする（an の n を 1 秒あけて打ち、次の語 not を n から打つ）。次の語に入れた字がどれも続きの字でもある間だけ残す
  - 戻すのも遅れて飲むのも外すのも、次の語でミスになるはずの打鍵だけ（×を増やす方向には働かない）。残り: 続きを打ち間違えた後（gymnaisum の i から先）は次の語の打鍵になる（docs/BACKLOG.md）
  - 続きを打ち終えてから Enter（打ち終えたら Enter で次への癖）: Study の「打ち終えてから 1.2 秒の Enter は次の語の答えを開かない」守り（`ECHO_AFTER_DONE_MS`）を、続きの最後の打鍵から数える。窓の外で続きの最後の字が次の語の頭として通った直後（1.2 秒）の Enter／Esc も、その字を次の語から外して答えを開かない（1 打 0.9 秒の gymnasium の m と次の語 moon）
- 経路は 3 つとも同じ: 物理キーの keydown、画面キーボード（`#input` に keydown を合成）、Android の input イベント（`handleTextInput`。1 字ずつ値が伸びる Gboard でも、予測変換で gymnasium と一度に入っても、gym で完成して残りは捨てる。gymna まで一度に入って残りを 1 字ずつ打っても同じ）。input 経路は値の a-z しか見ないので、空白・ハイフンを含む続き（a → a large、rest → rest api）は続きの頭の a-z 以外を読み飛ばして比べる
- 次の語が全文入力（Enter で判定）のときは、英単語の続きを持ち越さない（全文入力は 1 打ずつ判定しない。物理キーだけ飲んで input 経路では飲まない、という食い違いを作らない。ローマ字の続きの扱いは以前のまま）
- 綴り違い・別解の案内への影響: 出題語の後ろに字を足す形の綴り違い（programme・maths・towards・dialogue・an など、全パック有効で打てるもの 43 組）は出題語の所で正解になり、「X も正解（この教材では Y）」の行は出ない（記録は以前と同じ自力の正解）。出題語で始まる長い別解（gymnasium など 155 組）は、以前の「別解の案内（×なし・自力にならない）」ではなく出題語の自力の正解になる
- 対象外: 語形変化（apples の s・travelled の led・children の ren など、候補に無い続き）は今回は飲まない（docs/BACKLOG.md）


## タイピング練習（/typing.html）のキー（2026-10-09、Batch 59。docs/SPEC_TYPING.md）

- 見本を見てそのまま打つ写し打ち。キーは **document の keydown** で受ける（`#input` に焦点が無くても打てる。画面キーボードは `#input` に keydown を合成して投げ、それが document まで上がる）。英単語も日本語も `romajiKeyOf(event)` で取る（IME オンの `Process`・JIS かな配列・Shift つきも物理キーの位置。Study の英単語は `event.key.length !== 1` で返すので IME オンの人は詰まるが、それを真似しない）
- ミスは数えるだけ（語は止めない。正しいキーで進む）。Study の 1 ミス＝不正解とは別物。学習記録・`spelldash_key_miss` には書かない

| キー | 始まる前 | 打っている間 | 結果 | 読み込み中・読めない |
|---|---|---|---|---|
| ローマ字のキー（a-z・0-9・`-`・`'`） | 時間を測り始め、そのキーを判定 | 判定（正しい／ミス／飲む） | 何もしない（勝手にやり直さない） | 何もしない |
| ほかの 1 文字のキー（`/` `.` `,` `;` など。修飾キーなし） | 既定 | 数えない・`preventDefault`（Firefox のクイック検索に取られない） | 既定 | 既定 |
| Backspace・Delete | `preventDefault` だけ | 同左（打った字は消せない） | 何もしない | 何もしない |
| Esc | 何もしない | 始まる前に戻す（結果・自己ベスト・計測なし） | もう一度 | 何もしない |
| Enter・Space | 時間を測り始める（判定しない） | 数えない（語のあとの癖の空白を減点しない） | 結果から 0.6 秒以降なら もう一度 | 何もしない |
| Enter・Space（焦点がボタン・リンク） | 既定（押す） | 既定。ただし種類のタブ・「ご意見・不具合」の上では押させない（keydown・keyup・キーで起きた click を止める） | 既定（守りの 0.6 秒は結果のボタンが `inert`） | 既定 |
| IME 確定の Enter（`isComposing`・`keyCode 229`）・押しっぱなし（`repeat`） | 数えない | 同左 | 同左 | 何もしない |
| Ctrl・Cmd・Alt つき | 既定（再読み込み・コピーを止めない） | 同左 | 同左 | 同左 |
| ページが裏に回る（`visibilitychange`） | 何もしない | 始まる前に戻す（離れていた時間で打/分が下がった結果を出さない） | 何もしない | 何もしない |

- 扱わない場所: `[aria-modal="true"]` が見えている（ご意見の窓）、対象が `#input` 以外の入力できる要素。Tab は閉じ込めない（文字のキーは焦点がどこにあっても数える）
- **画面キーボードを借りる**: `initializeKeyboard({ playingClass: "typing--live", forceOnTouch: true })`。`playingClass` は「プレイ中」の印の body の class（既定 `home--playing`）、`forceOnTouch` は設定が「オフ」でもタッチ端末なら盤面を出す（入力欄が読み取り専用で OS キーボードが出ないため。既定 `false` で、今までどおりローマ字のカードだけ）。引数なしの Study（js/main.js）は 1 文字も変わらない。Enter は CSS で隠し、英単語では 3 段目（空白・ー・Enter）ごと隠す（高さの予約 `--osk-h` は変えない）。日本語では `body.romaji-answer` で ー を出す
- `getOskMode()` は `localStorage.getItem` が投げる端末（サイトのデータを拒否した端末）では `"auto"` を返す（以前は投げていた: Study は js/main.js の頭の `initializeKeyboard()` で止まってホームが描かれず、refreshKeyboard のたびにも uncaught の例外になっていた。Study も同じ直しが効く）
- **結果の 0.6 秒の守り**: 時間切れの瞬間に盤面を畳むと、盤面を叩いていた指の次のタップが下から現れた本体へのボタンに落ちる。結果が出てから 0.6 秒は盤面を出したまま・結果のボタン群を `inert` にし、0.6 秒後に畳む。keyboard.js は `spelldash:game-end` だけでなく **body の class の変化でも**盤面を畳む（MutationObserver）ので、守りの間は `typing--live`・`romaji-answer` も外さない
- **語末の ん の扱いが Study と違う**: 手本が語末の ん を n 1 つで見せるので、手本どおりに打つ人の次のキーを飲まないよう、次の語の 1 打目として通るキーを先に取る。通らず 0.6 秒以内で終えた語の続き（nn の 2 つ目の n）として通るなら飲む。Study は続きの窓の中では続きが先（速い人の次の語の 1 打目を飲んでも、次のキーで分かれば次の語に戻す。上の「英単語: 出題語が別の正解の先頭部分のとき」）
