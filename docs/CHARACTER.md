## 0. 前提思想

SpellDashは「英単語学習アプリ」ではなく **『世界一継続される英単語サービス』** を目指す。
単純な学習効率より、**毎日開きたくなる理由・感情的な愛着・小さな成功体験・習慣化** を最優先する。

## 1. プロフィール

| 項目 | 内容 |
|---|---|
| 名前 | はすみ（Hasumi） |
| 愛称 | はちゃん |
| 役割 | 未来サポーターAI（先生ではなく**学習パートナー**）。書斎（ホーム、2026-10-08〜）では **とんがり帽子の見習い魔法使い**: 窓辺の腰掛けで本を読んでいる。先生でも案内役でもなく、同じ部屋で先に勉強している見習い |
| 性格 | 優しくて落ち着いているけど、喜怒哀楽がとっても豊か |
| 好きなこと | おいしいもの、カフェ巡り、みんなの「できた！」を見ること |
| 夢 | みんなと一緒に、もっといろんな景色を見に行くこと |
| キャラクターカラー | 創業者が用意した絵の色のまま: 帽子・ケープ・衣は藍がかった紺、帽子の帯・縁取り・三日月の飾り・留め具は金、襟とケープの裏地は生成り、髪は栗色のボブ、目は茶、本は赤茶の革に金の箔、靴は茶の革。窓辺の場面に焼くときだけ部屋の光に寄せる（§2.5）。画面用の純色（旧 **#8D70FF** など）は部屋に出さない（docs/CONCEPT.md §3.2） |

**立ち位置**: ユーザーが主人公。はちゃんは一緒に頑張る伴走者。**はちゃん自身が主役になってはいけない。**
役割は「応援・共感・励まし・成長を一緒に喜ぶ」のみ。

**目指す感情**: ユーザーが「今日は疲れたけど、5分だけやろうかな。」と思える存在。勉強を強制する存在ではない。

## 2. 表現ルール（NG / OK）

### 絶対NG（この方向に進めない）

### OK例

## 2.5 絵（2026-10-17〜、創業者が用意した絵。docs/CONCEPT.md §3.8）

絵は創業者が用意した 1254×1254 の透過 PNG（006 お出迎え・007 考え中・008 学習成功・009 再挑戦の応援・010 読書。part-02 の 021〜030 は届いたら見直す）。元の PNG はリポジトリに入れず、`node scripts/build-hasumi.mjs --src <元の絵の置き場>` が配信する絵を作る（`--check` で作り直した絵が木の絵とバイト単位で同じかを見る）。

- **顔**: 正面向き・大きな茶の目（光の点が入る）・小さな口・頬にうすい赤み。表情は 2 つだけ使う: ふつう（006 の顔）とうれしい（008 の目を閉じた笑顔）。
- **体つき**: 2.5〜3 頭身。座る・立つは絵のとおりで、描き足さない。
- **服**: 藍のとんがり帽子（先が後ろへ折れて巻く・金の帯・三日月の飾り・広いつばに金の縁）、藍のケープと衣（生成りの裏地・金の縁取りと星の刺繍）、生成りの襟と金の留め具、茶の靴。服装・小物を増やさない（Phase 2 の季節衣装は創業者判断）。杖・使い魔は出さない（彼女は勉強している見習いで、魔法を使う場面は無い）。
- **光の扱い**: 部屋で光るのは炎だけ。010 の本の頁の光は抑える（頁の上に黄の補色を乗算で重ねて紙の白に戻し、頁の上に浮く光の霞を消す）。窓辺に焼くときは部屋の光に合わせる: 昼は北窓（背後の左上）に合わせて冷たい色に寄せ（彩度・赤を引く・コントラストを浅く）、左上の縁に窓の光、座面に短い影。夜はろうそくの部屋の明るさに暗く暖かく沈め、上の縁に月の光（帽子のつばと山が暗い空に沈まない）、右の縁にろうそくの照り返し。値は `scripts/room-art/scene.mjs` の `FIG_LOOK`・`FIGURE`。
- **本体は部屋の絵の中**: ホームの部屋の帯（`assets/images/room/scene-*.webp`）の窓辺の腰掛けで本を読んでいる（010）。幅は窓の開口の 0.6 強で、夜の窓の月を隠さない。
- **一言は紙片**: 窓の脇に真鍮の鋲で留めた羊皮紙（`#hasumiHome .hasumi__bubble.slip`）に 1 文。ホームでは隣に丸いアバターを置かない（絵の中にいる人の隣に 2 人目を置かない）。
- **丸いアバター（32px）**: 結果のパネル・週間レポート・学習中の知らせだけ。`assets/images/hasumi-normal.webp`（ふつう: 006 の顔）／`hasumi-happy.webp`（うれしい: 008 の顔）＋ `@2x`。大きさ・金の 1px の枠・紙の吹き出しの組みは前と同じ。
- **縮小の決まり**: アバターは元の絵の顔の正方形（中心 666,400・一辺 440。帽子のつばの縁から襟まで入り、008 の右のきらめきは入らない）を半分ずつ縮めて 64px と 32px（一度に大きく縮めると細い線がちらつく）。表示 32px に対して 1x と 2x（32px ≤ 2.5KB・64px ≤ 5KB）。窓辺の姿は 010 を外接矩形で切り詰めて幅 300px（`scripts/room-art/figure-reading.webp`。配信しない）にし、場面を 2 倍の画素で焼く（`node scripts/room-art/render.mjs`。phone ≤ 40KB・short ≤ 32KB・desk ≤ 50KB）。上限を超えたら生成器は書かずに止まる。
- **画像に文字を焼き込まない**。絵の中の文字・数字・記号を足さない。

## 4. 実装フェーズ

- **Phase1（実装済み）**: ホーム一言・結果のパネル・週間レポート＋学習中の知らせ（§3）。ユーザー反応を見る
- **Phase2（反応を見てから検討）**: 季節衣装・スタンプ・シェア画像・イベント

実装の実体:
- `js/hasumi.js` — セリフ選択＋吹き出しUI（トーン規則をコードコメントにも明記）。呼び手は `js/game.js`（結果のパネル 2 か所・学習中の知らせ 2 か所）と `js/weeklyReport.js`（週間レポート）
- `assets/images/hasumi-normal.webp`（ふつう）/ `hasumi-happy.webp`（うれしい）＋ `@2x` — 創業者の絵 006／008 の顔の丸アバター（結果のパネル・週間レポート・学習中の知らせ）
- 書斎（ホーム）: 部屋の絵の窓辺（§2.5）。一言は `renderHasumiHome()` が紙片に描く（`<img>` は出さない）
- 絵の生成: `scripts/build-hasumi.mjs`（元の PNG → アバター 4 枚・窓辺の姿・場面 6 枚）、`scripts/room-art/render.mjs`（場面だけ焼き直す）

2. 学習体験を邪魔しないか？

4. 習慣化につながるか？
5. 愛着が生まれるか？

## 8. スマホUI原則（キャラ表示にも適用）

- 主戦場はスマホ（通勤・通学・寝る前・SNS導線）。PC最適化よりスマホ体験優先
- **スクロールしない。1画面1目的。学習の邪魔をしない**
- Study画面に置いてよいもの: 残り時間・単語・入力欄・最小限の情報・**小さな**はちゃん
- UIは極限まで削る
