# 分野パック（場面カード集）のデータ形式

ニッチな業務領域の用語を「場面（意味）→ 用語」の場面カードで学べるようにするための教材単位。
`data/packs/<packId>.json` に1ファイル1パック。ユーザーは「単語帳」ページの教材ライブラリで追加すると、
ホームのカテゴリに現れて Study／Challenge で出題される（追加しない限り読み込まれない）。

## ファイル

```json
{
  "subject": "english",
  "category": "<packId>",
  "label": "不動産 実務",
  "blurb": "賃貸・売買の現場で毎日出る用語。契約・重説・ローン・管理まで",
  "audience": "不動産会社の新人、宅建の勉強を始めた人",
  "genres": { "re-rent": "賃貸の流れ", "re-sale": "売買の流れ", "re-law": "法律・重説" },
  "words": [ ...カード ]
}
```

- `category` は `manifest.json` の id と一致させる。英小文字（例: `realestate`）
- `genres` は `tags[0]` → 表示名。パック内で使う全ジャンルを載せる（未登録のタグは検証で NG）
- `blurb` は40字以内、`audience` は30字以内（ライブラリのカードに出る）

## カード（1枚）

```json
{
  "id": "concept-re-jusetsu",
  "en": "re-jusetsu",
  "kind": "concept",
  "answer": "重要事項説明",
  "accept": ["重説", "重要事項の説明"],
  "ja": "契約前に宅建士が物件と取引条件を説明する手続き",
  "q": "契約の前に、宅地建物取引士が物件の権利関係や設備、取引条件を書面で説明する。買主・借主が納得してから判を押すための手続き",
  "explain": "宅建士の記名と説明が必要。契約書（37条書面）とは別の書類",
  "level": "easy",
  "tags": ["re-law"],
  "say": "important matters explanation"
}
```

| 項目 | ルール |
|---|---|
| `id` | `concept-<en>` に一致 |
| `en` | `<パック接頭辞>-<英字キー>`。英小文字・数字・ハイフンのみ。**他パックと衝突しないよう必ずパック固有の接頭辞**（例: `re-`, `acc-`, `hr-`） |
| `kind` | `"concept"` 固定 |
| `answer` | 打つ答え。日本語の用語・略語（大文字）・英単語（小文字）。40字以内。**q の中に answer の文字列を入れない** |
| `accept` | 別解 0〜6個。略称・正式名称・カタカナ・英語表記・よくある表記ゆれ。判定は NFKC 正規化＋小文字化で比較されるので、大小文字違いは不要。**answer が日本語（かな・漢字を含む）なら、ひらがなの読みを必ず 1 つ入れる**（読みをローマ字で打つ。下の「読み」）。**answer が英字とハイフンだけ（CPC・Cu・EU。綴りを 1 字ずつ打つ）なら、綴りで打てる語だけ**（半角の英字・数字・記号・空白: `cost per click`・`rel=canonical`）。日本語の名前・読み（クリック単価・銅・どう）は綴りでは打てず判定に使われないのに、単語帳の「別解」に正解として出るので書かない（validate-words が NG。Batch 73）。見せたい・検索で引きたい日本語の名前は `aka` に。空白・数字・記号の入った別解は物理キーで打てるが、画面キーボード（a〜z）にそのキーが無いのでスマホでは打てない（答えは打てる。docs/BACKLOG.md） |
| `acceptReadings` | accept の漢字の別表記ごとの読み `{ "<別表記>": "<読み>" \| ["<読み>", …] }`。accept の直後。読みは accept にも入れる。下の「別表記の読み」 |
| `aka` | 表示と検索だけの名前（PR #191 のレビュー）。answer が英字とハイフンだけのカード（綴り入力）だけに書く。日本語の名前（CRM の `顧客管理システム`・EU の `欧州連合`）。accept の直後。単語帳の「別名: …」と語の詳細に出て、単語帳の検索で引ける。**判定・ヒント・タイピング練習には使わない**（別解ではない）。空でない文字列の配列で、重複しない・答えと同じでない・綴り入力で打てる語は書かない（打てる語は別解なら accept に）。書かないもの: 読み（ひらがな・`シーエスエス` のように英字を 1 字ずつ読んだカタカナ）・答えに字を足した派生の語（`SSL化`・`NISA口座`。答えで引ける）・答え・要約・問題文・解説にもう同じ字がある語（Cu の 銅）（validate-words が形・重複・答えと同じ・打てる語・綴り入力のカードでない を NG） |
| `ja` | 意味の要約（30字前後）。一覧と答え表示に出る |
| `q` | 場面・意味の説明。30〜120字。「誰が・いつ・何をする場面か」が分かる具体的な文。答えが推測できる手がかりは入れるが、答えそのものは書かない。答えの字は言い換えで指す（答えの字がすべて答えの 2 字以上の並びとして問題文に出ると写すだけで打てるので、品質の規則 Q18 に当たる。入塾テスト は「塾に通いたいと申し込んだ生徒に、授業が始まる前に解いてもらう問題」。Batch 73） |
| `explain` | 答えの後に出る1行の補足（80字以内）。定義の言い換えではなく「現場で効く一言」（混同しやすい語、なぜ重要か、式、数字の目安） |
| `level` | `easy`（その業界で最初に覚える語）／`normal`（1年目に出る）／`hard`（経験者・資格レベル）。目安は 4:4:2 |
| `tags` | `[ジャンル, ...]`。先頭がジャンル（`genres` に登録）。略語なら `"abbr"` を2つ目に |
| `say` | 発音に使う英語（略語の正式名称や英訳）。英語が無い用語なら省略。答えが日本語のカードでは読まない（Batch 58） |

## 内容の方針

- 1パック 40〜60枚、ジャンル 4〜8個。業界の「共通言語」を一通り、入門から順に
- 正確さ最優先。年ごとに変わる数字（税率・保険料率・上限額）は書かない。書くなら「目安」と明記
- 差別・断定・法的助言に読める表現は避ける
- 同じ answer をパック内で重複させない。他パックとの重複は可（別 id なので統計は別）

## 検証

```bash
node scripts/validate-words.mjs   # data/english と data/packs をまとめて検証
```

- 形式・重複・`genres` の網羅・`manifest.json` の `count` との一致を確認する
- 綴り入力のカード（答えが英字とハイフンだけの概念カード。盤面と同じ `js/wordData.js` toCard → `js/judge.js` answerModeOf で決める。計算カードを除く）の accept に、綴りで打てない字（日本語・全角）があれば NG（Batch 73）。打てる字（半角の 0x20〜0x7e: 英字・数字・記号・空白）の決め方は `js/answers.js` の `isSpellAlt` の 1 か所（判定の候補 `acceptedAnswers`・マイ単語帳・判定のシミュレーションの untypeable も同じ所を読む。前の `scripts/lib/spell-typeable.mjs` と同じ決まり）。英字で始まる日本語の別解（SSL の https化・NISA の NISA口座）は、打ち終えられない英字の頭を × にしない・ヒントで日本語の字が入る・出題語の続きの持ち越し止めで次の語の速さを測らない、の欠陥にもなる。Batch 73 で 828 件・306 枚を外した（元の値は main d8ea9c6）。空白・数字・記号の入った英字の別解は物理キーで打てる正しい別解なので NG にしない（画面キーボードで打てないのは docs/BACKLOG.md）
- 数は、綴り入力の概念カードの全部（accept の無いカードも数える）と、accept が 1 語以上の枚数を出す
- `aka`（表示と検索だけの名前）: 綴り入力の概念カードだけ・空でない文字列の配列・重複しない・答えと同じでない・綴り入力で打てる語でない（打てる語は別解なら accept に）。PR #191 のレビューで、Batch 73 で外した名前のうち 596 語（285 枚）を戻した（戻さなかった読み・派生の語・ほかの欄にもう同じ字がある語の決まりは上の `aka` の行）

## 品質の規則と基準線

形式の検証（validate-words）の後に、教材の質の規則を流す。CI の checks でも同じものが流れる。

```bash
node scripts/quality/check.mjs              # 全部の規則を流し、基準線と比べる（規則ごとに 基準線 → 今 の数を出す）
node scripts/quality/check.mjs --list=Q04   # その規則の当たりを 1 行ずつ（+ は基準線に無い当たり、- はもう当たらないカード）
node scripts/quality/check.mjs --update     # 基準線を下げる（誤りの規則はもう当たらないカードを消すだけ。--update=Q03,Q04 でその規則だけ）
node scripts/quality/check.mjs --update --add=Q05  # その規則は新しい当たりも基準線に足す（新しい規則・規則や判定器の変更のときだけ。下に）
node scripts/quality/check.mjs --base=<木>  # 前の木（PR の向け先。その木の data/ と scripts/quality/baseline.json を読む）とも比べる（CI の PR はこれ）
node scripts/quality/test-check.mjs         # 比べ方そのものの検査
node scripts/quality/sim-judge.mjs          # 判定器で全カードを打つ（答え・読み・別解・競合語を打ち切ると正解か、何打目で × か。--tsv <file> で 1 件 1 行）
node scripts/test-judge.mjs                 # 判定器（js/judge.js）の単体の検査
node scripts/quality/review-readings.mjs    # 反証の手がかり（CI では流さない）: 別表記に結んだ読みのうち、データの漢字の読みで裏付けの無い組（--base=<木> で変わったカードだけ）
```

- **新しいパック・カードを足す PR は、誤り（error）の規則で新しい当たりを 0 にする**。新しく足したカードが当たったら、基準線に足さずにカードを直す
- **基準線**（`scripts/quality/baseline.json`）は「規則 → その時点で当たっていたカード（`カテゴリ id:カード id`。パックそのものは `パック id:*`）」の一覧。前からある当たりは基準線に入っているので PR を落とさない。基準線に無いカードに当たる・当たりの数が増えると落ちる
- **基準線にもうあるカードを変えるとき**（Q04 の読みを足す・別表記を外すなど）: 基準線はカードの一覧なので、そのカードに新しい欠陥（読みの無い別表記をもう 1 つ・× になる別解）を足しても基準線だけでは気づけない。CI の PR は `--base` で向け先の教材も今のコードと規則で流し、変わったカードに前に無かった中身の当たりが出たら「変わったカードに新しい当たり」で落とす（出力の `*` の行）。これは `--update` では残せないので、そのカードの変更を直す。当たりが減る・同じ中身のまま残るのは落ちない
- **直して当たりが減ったら、同じ PR で `--update` して基準線を下げる**。下げ忘れると「基準線が古い」で落ちる（直したカードがまた壊れても気づけるように、基準線は下がる一方にする）
- **`--update` は誤りの規則の基準線を下げるだけ**（もう当たらないカードを消す）。新しい当たりは足さないので、教材を変えて出た新しい当たりは `--update` しても落ちたまま。カードを直す。警告・情報の規則は `--update` で今の当たりに合わせる（落とさない規則なので、数の推移を基準線の差分で見る）
- **基準線に新しい当たりを足すのは `--update --add=<規則>` の明示だけ**。使うのは (1) 新しい規則を足したとき、(2) 規則や判定器（`js/judge.js`・`js/answers.js` など）を変えて、前からある教材に当たりが見つかったとき。PR に理由を書く
- **CI の PR は基準線を上げたかも見る**: 向け先の基準線（`git archive HEAD^1 data scripts/quality/baseline.json`）と今の基準線を比べ、誤りの規則で向け先の基準線に無いカードを足した（数を上げた）なら「基準線を上げた」で落とす（出力の `^` の行）。除くのは、向け先の基準線に無い規則（その PR で足した規則）と、向け先の教材でも今のコードと規則で当たるカード（上の (2)。前からある当たりが見つかっただけ）。教材の変更から来た当たりは `--add` でも残せない
- 警告（warn）の規則は数を出すだけで落とさない。数の推移は基準線の差分で見る
- 規則を足すときは `scripts/quality/rules/<id>.mjs` に 1 つ置き（`export default { id, level, describe, run(ctx) }`。ctx は `scripts/quality/ctx.mjs`。全カードをゲームと同じ形で読む。`js/` のモジュールは `ctx.modules` から使い、規則のファイルから `js/` を import しない〔`--root=<木>` で別の木を流すとき、その木のコードで判定するため〕）、`--update --add=<id>` で基準線に入れる
- 別解は迷ったら足さない（上の「誤った別解は入れ忘れより有害」と同じ）。Q04 の当たりは、同じ意味なら読みを足し、違う意味か判断がつかなければ外す
- 誤りの規則の当たりは、学校でないカードでは Q04・Q05（分野パック。FOUNDER_TODO 10 の承認待ち）のほかは 0（Batch 73 で Q01・Q06・Q09・Q18 を 0 に）。残る Q18 41 枚は学校のパックの問題文で、書き換えは創業者が見る（基準線に残る。件と案は docs/BACKLOG.md の Batch 73）

| 規則 | 段 | 中身 |
|---|---|---|
| Q01 | 誤り | 基本カテゴリの概念カードの問題文に、答えか別解（2 字以上）がそのまま出る（パックは validate-words が止める） |
| Q03 | 誤り | accept に同じ語が 2 度ある・答えと同じ語がある（NFKC・小文字で比べる。判定は変わらないが単語帳の「別解」に同じ語が並ぶ） |
| Q04 | 誤り | 日本語の答えのカードの accept に、読みを結んでいない漢字の別表記がある（答えと漢字の並びが違う B・C 型: 定期保険／定期死亡保険、電子線／陰極線。読みがあるかを機械で決められないので、`acceptReadings` で結ぶ。下の「別表記の読み」）。結んだ読みが空・ひらがなの読みの形でない・accept に無い・別表記の形に合わない（かなが同じ順で出ない・漢字が読みの字数に合わない〔2 字以上の並びは 1 字 1〜4 字・1 字だけは 1〜5 字〕・数字の並びが位の読みの長さに合わない。下の「別表記の読み」）ものも当たる。漢字の並びが同じで「の」の有無だけ違う形は、その「の」の数の読みが無ければ当たり |
| Q04w | 警告 | 結んだ読みの見直しの候補: 答えの頭（尾）の形なのにほかの読みの頭（尾）にならない・同じ字面を答えにするカードの読みと違う・漢字が違うのに答えと同じ読み・別表記の無い短い読み（外した別表記の読みの消し忘れ。漢字の別表記が 1 つ以上あり全部結んだカードだけ。別表記の無いカードは結ぶ先が無いので見ない）・同じ別表記を別のカードで違う読みに結んでいる |
| Q05 | 誤り | 判定の再現: 答え・すべての読み・すべての別解を、盤面と同じ判定器（`js/judge.js`）で頭から打ち切ると × になる（1 打ミス・Enter で答えが開く）。答えと読みは Enter なしで正解になる。英字の別解は Enter で確定してもよい（advertisement の問いの ad）。漢字の別解は、同じ字面を答えにする別のカードの読みで打つ（辞書は使わない。読みが分からない別解は Q04 が数える） |
| Q06 | 誤り | 同じ例文（ex）を別の見出し語にも使っている |
| Q09 | 誤り | 同じカテゴリの英単語で、1 字の訳（かっこの外）が同じで綴りが違う（別解の索引は 1 字の訳を使わないので、互いに × になる。moon／month の「月」） |
| Q15 | 警告 | 同じ id の英単語の訳がパックによって違う（学習の記録は id で共有する） |
| Q18 | 誤り | 概念カードの答えの字が、すべて問題文の 2 字以上の並びに出る（漏れの率 100%。思い出さずに写せる） |
| Q18w | 警告 | 同じく、答えの字の半分以上が問題文に出る（漏れの率 50〜99%） |
| Q24 | 警告 | パックの説明（label・blurb・audience）に根拠の無い強い主張の語（網羅・頻出・毎回・公式・準拠・教科書・新出語・狙われる・約N割） |
| P1 | 誤り | 品詞が動詞なのに訳が名詞の形だけ（建物＝build）・品詞が名詞なのに訳が「〜する」だけ |
| P2 | 誤り | 品詞の札が違う語どうしが、同じ訳で別解として結ばれる（repeatedly〔副〕と repetition〔名〕の「繰り返し」）。別解の索引は、その訳の札が両方で確かなとき（訳が 1 つのカードの札。札はカードに 1 つで 2 品詞なら主な方なので、訳が 2 つ以上のカードの札はどの訳のものか分からない）だけ、この組を結ばない。札が確かでない組（circa〔前「およそ・〜ごろ」〕と approximately〔副「およそ」〕）は結ぶ（誤った × を出さない側）。札が確かで違っても同じ意味の組（till〔前〕と until〔接〕の「〜まで」）は、両方の accept に書けば別解になる。まとめ方は `js/answers.js` の `meaningGroups`・`crossesPos`（索引と規則が同じものを使う） |
| P3 | 警告 | 同じ id の英単語の品詞がパックによって違う |
| P4 | 警告 | 例文の語形（exForm）が、意味の違う別の見出し語と同じ綴り（build の例文の building は「建物」の綴り） |

## レベル別パック（英検・TOEIC）: 英単語形式

試験のレベルごとに英単語（en → ja）を集めたパック。場面カードではなく、通常の英単語カードと同じ「日本語を見て英単語を打つ」出題になる。
ファイルに `"cardType": "word"` を付ける。追加した人だけに出るのは分野パックと同じで、「すべて」や Daily Dash には混ざらない。

```json
{
  "subject": "english",
  "category": "eiken2",
  "cardType": "word",
  "label": "英検2級",
  "blurb": "高校卒業レベル。長文と英作文で頻出の1,200語のうち核になる語",
  "audience": "英検2級を受ける高校生・社会人",
  "genres": { "society": "社会", "science": "科学", "emotion": "感情", "action": "動作", "work": "仕事" },
  "words": [
    { "id": "english-negotiate", "en": "negotiate", "ja": "交渉する", "pos": "動", "level": "normal", "tags": ["work"] }
  ]
}
```

| 項目 | ルール |
|---|---|
| `id` | `english-<en>`（他カテゴリに同じ語があれば同じ id になり、学習記録を共有する。それでよい） |
| `en` | 英小文字とハイフンのみ。句・熟語は入れない（1語） |
| `ja` | 最も代表的な訳を1つ（必要なら2つを「・」で）。24字以内。試験でその語が問われる意味を優先。**見出し語そのものを書かない**（答えが出てしまう）。連語を示すときは伏せ字に: 「〜にもかかわらず（in ___ of）」。同じカテゴリのほかの語と、かっこの外が 1 字だけの同じ訳にしない（moon と month の「月」は互いに × になる。month は「1か月（暦の月）」。規則 Q09）。品詞の違う語と同じ訳の形にしない（形容詞は「違った」「まあまあの」、副詞は「ほとんど〜ない」のように品詞の形で書く。訳が 2 つ以上のカードの札は確かでないとみなされ、品詞の違う同じ訳の語と別解に結ばれる。Batch 73）。別解にしない語どうしは訳を共有しない。別解の索引は訳のかっこを落として比べるので、書き分けはかっこの外の字で（few「少数の・（数が）ほとんどない」と little「小さい・少しの」。PR #191 のレビュー対応） |
| `pos` | 品詞: `名` `動` `形` `副` `前` `接` `代` `助` `間`。2品詞なら主な方（別解の索引が品詞をまたぐ組を結ばないのに使うのは、訳が 1 つのカードの札だけ。上の規則 P2） |
| `level` | パック内の相対難易度。そのレベルの中で頻出・基本＝`easy`、標準＝`normal`、上位＝`hard`。目安 3:4:3（頻度順の生成パックは例外、下記） |
| `tags` | 先頭がジャンル（意味分野）。`genres` に登録 |
| `accept` | 任意。同じ訳に対して打たれうる、**英語として正しい別の語**（大きい → `big` に `["large"]`）。英小文字1語のみ。出題語そのもの・重複は不可。**迷ったら入れない**（誤った別解は誤答を正解にしてしまうので、入れ忘れより有害） |

- 1パック 110〜130語。同じパック内で重複させない。同じ試験の下位レベルに入れた語は上位に入れない（試験内で一貫させる）
- **別解（`accept`）について。** 訳を見て英単語を打つ形式では、1つの訳に正しい英語が複数あることがある（「大きい」に big と large）。出題語だけを正解にすると、正しい語を思い出した人が答えられない。アプリは自分のデータの中で同じ訳を持つ語を自動で別解にするが、その語がどのパックにも無ければ気づけない。そこを `accept` で補う。つづり違い（favourite / favorite）は別解ではなく同じ語として、打ち直させずに正解になる
- **頻度順の生成パック（ngsl / tsl / bsl）は 3:4:3 に合わせない。** これらは1本の頻度順リストを機械的に切ったもので、パック間に本物の難易度差がある（NGSL 1位の the と 2,800位の quantitative は別物）。`level` は出題の解放条件（`allowedWordLevels`）に使われるので、パックごとに 3:4:3 へ均すと、初心者が終盤のパックを選んだときに最上位の語が `easy` として出てしまう。語そのものの難しさ（CEFR-J 由来）を入れ、結果として前半のパックは easy 寄り・後半は hard 寄りになるのが正しい
- 「そのレベルで新たに覚える語」を選ぶ。全レベル共通の超基本語（the, is …）は入れない
- 級・スコア帯と語彙の対応は公式の語彙表が無いので「目安」。検定団体名や商標的な表現は label 以外で使わない
- **分野の英単語のパック**（Batch 74。`prog-english1`・`prog-english2`）も同じ形。群は「分野の英単語（<分野>）」（scripts/sync-packs.mjs の GROUPS・js/shelves.js の GROUP_SHELF で英単語の棚）。ジャンルの札は分野の接頭辞を付ける（`pw-value`。ジャンルの表示名は全パックで 1 つの表なので、`data`・`error` のような素の札はほかのパックの表示名になる）。訳はその分野での意味を先に書き、ふつうの意味を短く添えてよい（argument「引数・議論」）。製品名・会社名・言語名・サービス名は語にも例文にも書かない。外の頻度表を写さないので `source` は書かず、blurb で頻度順・網羅を言わない

## 公開する英単語（Batch 78）

公開の教材は「英単語」1 つ。中身は NGSL の 24 巻（`ngsl01`〜`ngsl24`）の 2,857 語（NGSL 1.2 の 2,809 語と、数・曜日・月の 48 語）。
どの id を公開し、どの順に学ぶかは `data/public/english.json` の 1 ファイルが持つ（公開する id の唯一の表）。カードの中身（訳・品詞・例文・別解）はパックのまま。
ほかのパックと利用者の記録は消さない（公開の対象から外すだけ）。出典は docs/LICENSES.md。

```json
{
  "v": 1,
  "id": "english",
  "label": "英単語",
  "total": 2857,
  "fnLast": 122,
  "packs": ["ngsl01", "…", "ngsl24"],
  "source": {"list": "NGSL 1.2", "title": "New General Service List", "authors": "…", "license": "CC BY-SA 4.0", "licenseUrl": "…", "url": "…", "changes": "…"},
  "order": [
    "english-zero",
    "english-two",
    "…"
  ],
  "rank": [0, 0, "…"]
}
```

| 欄 | 中身 |
|---|---|
| `total` | 公開する語数。生成器の `EXPECTED_TOTAL` と違えば落ちる。変えるのは創業者の決定のときだけ |
| `fnLast` | 最後に回した機能語（`tags[0]` が `fn`）の数。生成器の `EXPECTED_FN` と違えば落ちる |
| `packs` | 元の巻（この順に読む） |
| `source` | 出典（画面の出典の表示が読む）。`changes` は SpellDash が変えたことの 1 文で、補助の語と機能語の数から作る |
| `order` | 学ぶ順の id（1 語 1 行）。機能語でない語を巻の順のまま → 機能語を巻の順のまま最後に |
| `rank` | `order` と同じ並びの NGSL 1.2 の順位（CSV の SFI Rank）。NGSL に無い補助の語は 0 |

決まり（`node scripts/build-public-vocab.mjs --check` と `node scripts/test-public-vocab.mjs` が見る）:
1. manifest の ngsl01〜24 の count = 巻の語数
2. id は 24 巻で重ならない
3. NGSL 1.2 の CSV の語は、どれも `english-<語>` の id で表にある（順位は id で引く）
4. 巻の順・巻の中の順で NGSL の順位が下がらない。NGSL に無い語は ngsl01 の頭にだけ置く
5. 語数 = `EXPECTED_TOTAL`、機能語の数 = `EXPECTED_FN`
6. 並びと順位は上の `order`・`rank` のとおり
7. ファイル = 生成物（作り直して同じ文字列）

- **NGSL のパックで語を足す・消す・並べ替える・札（`tags[0]`）を変えたら `node scripts/build-public-vocab.mjs` で作り直す**（ずれると `--check` が落ちる）。訳・例文・別解だけの直しでは表は変わらない
- 札を `fn` に変える・外すと並びが変わるので、機能語の数で止める。数を変えるなら決定（機能語 122 語を最後に）と食い違うので、先に創業者に確かめてから `EXPECTED_FN` を直す
- 止めるのは数だけ。数が同じままの札のつけ替え（ある語を `fn` にして別の語の `fn` を外す）や、補助の語を NGSL に無い別の語に替えることは、作り直すと通る（作り直すまでは `--check` が「生成物と違う」で落ちる）。作り直したら表の差分（1 語 1 行）で、動いた語が意図どおりかを見る
- 同じ綴りで別の項目にする語（5月を助動詞の may と別にするなら `english-may-month`）は、NGSL の順位を持たない補助の語として ngsl01 の頭に置く。語数が変わるので `EXPECTED_TOTAL` も直す（創業者の返事待ち。今は5月の項目は無い）
- `data/public/` は教材ではなく表なので、validate-words・品質の規則の対象外。アプリが読むのは Batch 78 の後の段から（この表を足した時点では、画面・出題・記録は変わらない）

## 例文（英単語カード共通・任意）

英単語カード（`data/english/*.json` と `cardType:"word"` のパック）には例文を付けられる。答えを見た時・正解した時と、単語帳・単語詳細に出る。

```json
{"id":"english-negotiate","en":"negotiate","ja":"交渉する","pos":"動","level":"normal","tags":["contract"], "ex": "We need to negotiate a better price.", "exJa": "もっと良い値段を交渉する必要がある。"}
{"id":"english-go","en":"go","ja":"行く","level":"easy","tags":["action"], "ex": "I went to Kyoto last week.", "exJa": "先週、京都に行きました。", "exForm": "went"}
```

| 項目 | ルール |
|---|---|
| `ex` | 自然な英文、70字以内、1文。見出し語（または `exForm` の語形）を必ず含む。その語の `ja` の意味で使う。固有名詞は教科書の範囲（Kyoto, Ken, Emi） |
| `exJa` | 自然な日本語訳、40字以内。直訳より「日本人がその場面で言う言い方」 |
| `exForm` | 英文中の語形が見出し語と違うときだけ（went, better, studies, children）。同じなら書かない（検証で弾く） |

- 差し込みは `node scripts/add-examples.mjs <データ> <例文JSON>`（1行1語の書式を保つ。1項目1行に整形されたファイルは `words` だけを1行1語に直してから差し込む。内容は変えない）。例文JSONは `{ "<id>": { "ex", "exJa", "exForm"? } }`。終わったら `grep -c '"exJa"'` で語数と一致することを確認
- レベル感: そのカテゴリ／級の学習者が読める語彙で書く（例文の方が見出し語より難しくならない）
- 同じ英文を複数の語に使い回さない（規則 Q06。機能語・数詞の例文は名詞の例文と重なりやすい: the の Please close the door. は door と同じだった。直すときは機能語・数詞の側に、その語の意味で使う新しい文を書く。Batch 73）。数字は英単語で（two, not 2）

## 文法パック: 穴埋め形式

英文の空欄に入る語を英語で打つ。場面カードと同じ仕組み（`kind: "concept"`）で、`q` が「空欄つきの英文＋日本語訳」、`answer` が空欄に入る語。
ファイルに `"cardType": "grammar"` を付ける（出題ラベルが「空欄に入る英語を打つ」になり、発音は `say` の全文を読む）。

```json
{
  "subject": "english",
  "category": "grammar-jhs3",
  "cardType": "grammar",
  "label": "中学英文法 3年",
  "blurb": "現在完了・関係代名詞・分詞・間接疑問。高校入試で差がつく文法",
  "audience": "中学3年生、中学文法をやり直す社会人",
  "genres": { "g3-perfect": "現在完了", "g3-relative": "関係代名詞" },
  "words": [
    {
      "id": "concept-g3-perfect-been-to",
      "en": "g3-perfect-been-to",
      "kind": "concept",
      "answer": "have been",
      "accept": ["'ve been"],
      "ja": "現在完了（経験）",
      "q": "I ____ to Kyoto twice.（私は京都に2回行ったことがあります）",
      "explain": "「行ったことがある」は have been to。have gone to は「行ってしまって今いない」",
      "say": "I have been to Kyoto twice.",
      "level": "easy",
      "tags": ["g3-perfect"]
    }
  ]
}
```

| 項目 | ルール |
|---|---|
| `q` | 英文（空欄は半角アンダースコア4つ `____` を**ちょうど1か所**）＋全角カッコで日本語訳。訳と文脈から答えが1つに決まるように書く |
| `answer` | 空欄に入る語（1〜3語、小文字。文頭でも小文字。`I` だけ大文字）。判定は大小文字・空白を無視するので、表記ゆれは気にしなくてよい |
| `accept` | 短縮形（`'ve been`）や、文法的に同じく正しい別の埋め方。別解が多い問題は避けて文を直す |
| `ja` | 文法項目名（例: 現在完了（経験）、比較級、関係代名詞 which）。20字以内 |
| `explain` | なぜその形になるかの1行（90字以内）。よくある誤り・混同しやすい形に触れる |
| `say` | 空欄を埋めた完成文（英語のみ）。発音に使う。必須 |
| `tags` | 先頭が文法項目のジャンル（パック接頭辞つき）。`genres` に登録 |

- 1パック 60〜80枚。同じ文法項目に「基本形→疑問文・否定文→応用」の順で複数枚
- 空欄の語は英文の他の場所に現れないようにする（検証で弾かれる）
- 学習指導要領の区分は目安。学年の境目にある項目は、より一般的な扱いに寄せる

## 英作文パック: 英文を丸ごと打つ

日本語の文を見て、英文を丸ごと打つ。語順・時制・冠詞まで含めて判定するので、文法の「運用」の練習になる。場面カードと同じ仕組み（`kind: "concept"`）で、`q` が日本語文、`answer` が英文。
ファイルに `"cardType": "writing"` を付ける（出題ラベルが「日本語を英文にして打つ（項目）」になり、ヒントは1語ずつ、発音は `say`）。`"wordBank": true` を付けると、答えの語をシャッフルして問題文の下に見せる**並べ替え**形式になる（ラベル「語を並べ替えて英文を打つ」）。

```json
{
  "subject": "english",
  "category": "writing-jhs",
  "cardType": "writing",
  "wordBank": false,
  "label": "中学英作文",
  "blurb": "中学で習う文法で言える日常の文を、日本語から英文にして打つ",
  "audience": "中学生、中学英語をやり直す人",
  "genres": { "wj-perfect": "現在完了", "wj-relative": "関係代名詞" },
  "words": [
    {
      "id": "concept-wj-perfect-been-to",
      "en": "wj-perfect-been-to",
      "kind": "concept",
      "answer": "I have been to Kyoto twice.",
      "accept": ["I've been to Kyoto twice."],
      "ja": "現在完了（経験）",
      "q": "私は京都に2回行ったことがあります。",
      "explain": "「行ったことがある」は have been to。have gone to は「行ってしまって今いない」。回数は文末",
      "say": "I have been to Kyoto twice.",
      "level": "easy",
      "tags": ["wj-perfect"]
    }
  ]
}
```

| 項目 | ルール |
|---|---|
| `q` | 自然な日本語の文（15〜45字）。訳が複数あり得るときは全角カッコで指定語を添える: 「私は昨日その本を読み終えました。（finish を使って）」 |
| `answer` | 英文（2〜12語、通常の大文字・句読点）。判定は大小文字・空白・句読点・アポストロフィを無視するので、`Im` と `I'm` は同じ扱い。語順が違えば不正解 |
| `accept` | 同じ意味で同じ文法項目を使う別解（短縮形 `I've`／`I have` の両方、`will`／`be going to` が両方自然な場合など）。別解が3つを超える文は避けて q を絞る |
| `ja` | 文法項目名または場面（20字以内） |
| `explain` | 語順・時制・冠詞のポイントと、日本人がよくする誤りを1行（90字以内） |
| `say` | 英文（answer と同じ）。必須 |
| `tags` | 先頭が項目のジャンル（パック接頭辞つき）。`genres` に登録 |

- 1パック 60〜100枚。同じ項目で「肯定→疑問・否定→応用」の順に複数枚
- 固有名詞は Kyoto・Tokyo・Ken・Emi など教科書に出る範囲。数字は英単語で（two, not 2）
- 並べ替え（`wordBank: true`）は語の順だけが問題なので、10語以内の文にする

## 義務教育パック（社会・理科・国語・数学）: 日本語で答える場面カード

中学・小学の暗記項目を「説明 → 用語・人名・地名・年代」で答える。仕組みは場面カード（`kind: "concept"`）と同じで、答えは日本語。
ファイルに `"cardType": "school"` を付ける（出題ラベルが「説明に合う語を答える」になる）。

```json
{
  "id": "concept-jh1-yoritomo",
  "en": "jh1-yoritomo",
  "kind": "concept",
  "answer": "源頼朝",
  "accept": ["みなもとのよりとも", "頼朝", "よりとも"],
  "acceptReadings": {"頼朝": "よりとも"},
  "ja": "鎌倉幕府を開いた初代将軍",
  "q": "平氏を滅ぼしたあと、1192年に征夷大将軍に任じられ、鎌倉に武家政権を開いた人物",
  "explain": "弟の義経は平氏を滅ぼした立役者だが、対立して追われた。「いい国（1192）つくろう」は将軍任命の年",
  "level": "easy",
  "tags": ["jh1-kamakura"]
}
```

| 項目 | ルール |
|---|---|
| `answer` | 教科書の標準表記（漢字）。年代を問う場合は「1192年」のように数字＋年 |
| `accept` | **ひらがなの読みを必ず入れる**（読みをローマ字で打って答える。下の「読み」。答えが英字だけ〔EU・DNA・Cu〕のカードは綴りで打つので、読みも日本語の名前も accept に入れない。日本語の名前〔欧州連合・デオキシリボ核酸〕は表示と検索だけの `aka` に: 上の「カード（1枚）」の accept・aka）。主な読みを、かなの別解の先頭に。略称・別表記・旧称も（漢字の別表記には `acceptReadings` で読みを結ぶ。下の「別表記の読み」）。年代なら「1192」も |
| `q` | 教科書の説明に沿った具体的な文。答えの語は入れない。年代・地名など手がかりを1つ以上入れて答えが1つに決まるように |
| `ja` | 一言の要約（20字前後） |
| `explain` | 覚え方・関連事項・混同しやすいものを1行（90字以内）。語呂合わせ可 |
| `level` | その学年の中での基本／標準／発展 |

- 学習指導要領・検定教科書で標準的に扱う内容だけ。学説が分かれる年代（鎌倉幕府の成立年など）は、q の中で「征夷大将軍に任じられた年」のように問い方を限定する
- 現在も変わりうる統計（人口・生産量の順位）は「〜年時点」を書かないと使えないので避けるか、順位が安定しているものだけ
- 漢字の読みを問うパックは answer をひらがなにする（accept は不要）
- **問題文に読みが書いてあるカード**（同音異義語の書き分け「同じ音『たいしょう』の…」、漢文の句法「『いまだ〜ず』と読み…」など）は `"kanjiOnly": true` を付け、accept に読みを入れない。読みが q に書いてあるのに accept にもあると、q を写すだけで正解できてしまう（検証: accept の語が q に含まれていたら NG）
- **kanjiOnly のカードは学習に出さない**（2026-10-08〜）。答えは読みをローマ字で打つので、漢字の書き分けは問えない。データは残す（記録・単語帳の古い行のため。`findWord` では引ける）が、`getWordsByCategory` が外すので、Study・Challenge・ミッション・単語帳の一覧・語数に入らない。manifest の `count` とパックの入口ページの枚数は変えない（jkokugo2 は 10 枚、hs-kanbun は 30 枚が出題されない）。読みが 1 字で問題文に出ている・1 打で当たる字（漢文の 不・乎・矣）も kanjiOnly にする

## 読み（日本語の答え・2026-10-08〜）

日本語の答えは、漢字に変換せず**読みをローマ字で打つ**（`js/romaji.js`。かなの下に打ったキーを出し、1 打ずつ判定、読みを打ち終えたら Enter なしで正解）。読みの候補は `[answer, ...accept]` のうち、NFKC → カタカナをひらがなに → 記号・空白を落とす → 小文字、の結果が ひらがな・ー・a-z・0-9 だけになるもの（データの順）。

- 答えを見せるときの読みは、ひらがなを含む最初の候補。**答えそのものの読みを主な読みとして、かなの別解の先頭に置く**（答えがかなだけなら答えそのもの）。カタカナの言い換え（領収書 に レシート）や略語（浸潤麻酔 に しんま）は別解としては良いが、答えの読みの後ろに。答えの読みが無いと、答えを思い出した人が打てない
- 英字・数字を含む読みは、そのとおりに打つ（X線 → `Xせん`、PKO協力法 → `PKOきょうりょくほう`）。ただし**数字なしで打てる読みを 1 つは入れる**（スマホの画面キーボードに数字が無い。36協定 → `さぶろくきょうてい`）
- 1〜2 文字の英字だけの別解（単位記号 N・J など）は、かなの読みの打ち始めと同じキーで終わってしまうので入れない
- どの読みでも打ち終えた時点で正解になる（長い読みの手前に短い読みがあれば、短い方で終わる）。短い読みは、それだけで正解にしてよい語にする
- 検証（`node scripts/validate-words.mjs`）: 日本語の答えのカード（kanjiOnly・計算カードを除く）に、読みの候補がある／ひらがなを含む読みがある／主な読みが答えより短くない・答えにカタカナが無いのにカタカナでない／読み（3 字以上）が問題文に出ていない（カタカナとひらがなは同じに見る）／a-z と ー だけで打てる読みがある／各読みの標準の綴りで打ち終えられる／acceptReadings の形・キーが accept にある・読みが accept にある／学校のパックと基本カテゴリは、読みでない別表記をすべて結ぶ
- 既存のカードへの読みの書き足しは `node scripts/add-readings.mjs`（読みの台帳から accept の末尾に足す。ファイルの体裁を保つ。漢字の別表記の読みは台帳の `alts` で結ぶ: 下の「別表記の読み」）

## 別表記の読み（acceptReadings・2026-10-17〜）

accept の漢字の別表記（読みでない別解: 岩宿・厩戸王・菱形）には、その読みを `acceptReadings` で結ぶ。読みは辞書どおり。結んでいない漢字の別表記は、読みがあるかを機械で決められないので、品質の規則 Q04 に当たる。

```json
"accept": ["しょうとくたいし", "厩戸皇子", "うまやどのおうじ", "厩戸王", "うまやどのおう", "うまやとおう"],
"acceptReadings": {"厩戸皇子": "うまやどのおうじ", "厩戸王": ["うまやどのおう", "うまやとおう"]},
```

- 置く場所は accept の直後。無いカードには書かない（空のオブジェクトも書かない）。キーは accept の文字列そのまま（NFKC などで寄せない）・読みでない・かなか漢字を含む（英字の別解 signifié などは結ばない）。値は読み（慣用の読みが 2 つなら配列。キーの中で重複しない）。キーの並びは accept の並び
- 読みは accept にも入れる。判定・単語帳・タイピング練習の教材は今どおり accept から読みを作り、acceptReadings は読まない（どの読みがどの別表記のものかの記録。js/ は変えていない）
- 書いてよいのは日本語の答えのカード（kind が concept・計算／kanjiOnly／英作文／穴埋めでない・答えがかなか漢字を含む）だけ。答えそのものの読みは書かない（主な読みは今どおり accept のかなの先頭）
- 結んだ読みは、別表記の形に合う（`scripts/quality/readingShape.mjs`。辞書を使わない粗い見張り）。合わなければ Q04 に当たる。決まり（PR #187 のレビューで見直した）:
  - 別表記のかな（ひらがな・カタカナ・ー）は、読みに同じ順でそのまま出る（大塩の乱 ← おおしおらん は「の」が無いので合わない）
  - 漢字は、2 字以上の並びなら 1 字に読みの 1〜4 字（大和魂 ← やまとだましい・玉蜀黍 ← とうもろこし）、ほかの漢字と並ばない 1 字だけなら 1〜5 字（志 こころざし・政 まつりごと・詔 みことのり・承る の 承 うけたまわ・1000年 の 年）。漢字にはさまれた ケ・ヶ・ヵ・カ（関ケ原・吉野ヶ里・一ヵ月）も漢字と同じ枠（並びの 1 字に数える）
  - 数字の並びは、0 でない数字 1 字に 1 字から（並び全体で 1 字から）、位の読みの長さの和まで（一の位 4・十 6・百 6・千 5 字、4 桁ごとに まん・おく・ちょう の 3 字。1000年 ← せんねん・100000 ← じゅうまん・1192年 ← 1192ねん）。数字 1 字に 1 字以上とはしない（位の読みで縮む）
  - 英字は 1 字に 1〜6 字（X線 ← えっくすせん・W杯 ← だぶりゅーはい・限界CPA ← げんかいcpa）。語として読む頭字語（LAN ← らん）は 1 字に 1 字に足りないので合わない（読みに英字のまま書くか、結ばない）
  - 単位の記号 ℃ ℉ ％ ‰ ° は 1 字に 1〜5 字（1000℃ ← せんど・50％ ← ごじゅっぱーせんと）。並んだ数字と 1 つの枠になるので、記号を読まない読みも字数が合えば合う（50％ ← ごじゅう は合う）。読む記号 ＆ × ÷ ＋ − ／ は 0〜4 字（Q&A ← きゅーあんどえー・2×4工法 ← つーばいふぉーこうほう・A/Bテスト ← えーびーてすと）。ほかの記号・空白は読まない
  - 緩めた分の数（今の教材の答えと主な読み 3,384 組・結んだ読み 826 組と、それから作ったわざとの読み違い。PR #187 のレビュー）: 正しい組を誤りにするのは 3,384 組で 2 組のまま（平塚らいてう＝ひらつからいちょう・オイル漏れ＝おいるにじみ）・826 組で 0 のまま・手で作った正しい組 32 で 8 → 1（LAN＝らん）。読み違いを通すのは、別のカードの読み 2,189 → 2,319／3,383・末尾に 3 字足す 3,006 → 3,096／3,384・読みを 2 回 2,264 → 2,852／3,384（漢字 1 字 5 字までにした分）、末尾 2 字落とす・頭 3 字落とす・かなを落とすは変わらない（2,651・1,788・15）。6 字までにすると、正しい組は同じで、通す読み違いがさらに 65・23・245 増えるので 5 字にした
  - 2 字以上の並びを 1 字 4 字に締め直した分（PR #187 のレビュー対応の仕上げ。同じ組で、締め直す前 → 後。`readingShape.mjs` の `PER_KANJI`・`KANJI_ALONE`）: 正しい組を誤りにするのは、答えと主な読み 3,384 組で 2 → 2・結んだ読み 826 組で 0 → 0・手で作った正しい組 106 で 1 → 1（LAN＝らん）・答えのほかの読み 754 組で 236 → 243（増えた 7 組はどれもカタカナの言い換えで、答えの字の読みではない: 傾聴 ← あくてぃぶりすにんぐ・主訴 ← ちーふこんぷれいんと など）。読み違いを通すのは、末尾に 6 字 2,782 → 1,936／3,384・読みを 2 回 2,852 → 2,286・3 回 743 → 148・別のカードの読み 2,319 → 2,192・末尾に 3 字 3,096 → 3,081、手で作った読み違い 24 で 19 → 15（岩宿 ← いわじゅくいせきあと・出口 ← でぐちでぐちでぐち などを捕まえる）。末尾 2 字落とす・頭 3 字落とす・かなを落とす・半分・入れ替え・1 字は変わらない。main（漢字 1 字 4 字）の 末尾に 6 字 1,943・2 回 2,264・3 回 135 とほぼ同じに戻った
- 同じ読みの書き換え（菱形／ひし形・濾過／ろ過・居る／ゐる）は主な読みに結ぶ。同じ読みを別のキーに結ぶのはよい（菱形・菱型 → ひしがた）
- 同じ意味でない・読みに迷う別表記は、結ばずに外す（外す別表記の読みが accept にあれば読みも外す。上の「誤った別解は入れ忘れより有害」）。短い形がそれだけでは答えにならない（直列／直列回路）・指標や別の語（成約件数）・注記つきの同じ語も外す
- 学校のパック（`cardType: "school"`）と基本カテゴリでは、読みでない別表記をすべて結ぶ（`node scripts/validate-words.mjs` が NG にする。Q04 が数えない「漢字の並びが同じ」型〔取り締まり役／取締役〕もふさぐ。Batch 71 で学校と基本の 734 枚・別表記 933 件を結ぶか外し〔結ぶ 769・外す 164〕、既定にした）。分野パックは F10 の承認の後に広げる（それまでは結んでいない別表記が Q04 の当たりとして基準線に残る）

- 同じ字面の別表記は、どのパックでも同じ読みに結ぶ（憲法十七条 → けんぽうじゅうしちじょう は jhist1・hs-ethics とも）。文脈で読みの違う語（古語の 賢し: かしこし のカードでは かしこし、さかし のカードでは さかし）だけは別の読みに結んでよく、警告 Q04w に残る
- 書き足しは add-readings の台帳の `alts`（`{"id": …, "category": …, "readings": [], "alts": {"直列つなぎ": "ちょくれつつなぎ"}, "drop": ["直列"]}`。読みが accept に無ければ末尾に足し、acceptReadings に書く。別表記が accept に無い台帳は NG でそのファイルを書かない）。外すのは `drop`（結んだ記録と、その別表記だけに結んだ読みも消える。残る別表記の読み・主な読み・台帳の readings と alts の読みは残す）。もう結んである別表記を `alts` で別の読みに結び直すと、前の記録にあって新しい記録に無い読みも accept から外し、1 行ずつ「も外した」と出す（岩宿 の いわしゅく → いわじゅく・厩戸王 の [うまやどのおう, うまやとおう] → うまやどのおう。残す読みは drop と同じ。PR #187 のレビュー）。drop と結び直しで外す読みが答えの読みかもしれないとき（accept でその別表記より前にある＝別表記に結ぶ前からある読み〔alts の読みは別表記の後ろに足す〕、または前の記録で主な読みと一緒に結んである＝答えと同じ読みの異体）は、外さずに NG（「答えの読みかもしれない」）にしてそのファイルを書かない。残すなら台帳の `readings` に、外すなら `drop` に読みを書いて流し直す（竜頭蛇尾 の 龍頭蛇尾 ＝ [りゅうとうだび, りょうとうだび] を りゅうとうだび だけに結び直すと、前は答えの読み りょうとうだび も外していた。今の教材で同じ形は 32 枚・33 読み〔別表記より前 25・後ろ 8〕で、どれも NG になる。Batch 71 で足した読みはどれも別表記の後ろにあり、主な読みと一緒に結んでいないので、今どおり外して「も外した」と出す。PR #187 のレビュー対応の仕上げ）。体裁は accept の書き方に合わせる（1 行の accept の後ろに 1 行・1 行 1 カードは同じ行・JSON.stringify(_, null, 2) の形のファイルは整形し直す）
