## 3. 答え方の決め方（`modeOf(item, layout, env)`）

- 表は 1 項目 × 1 キーボードに答え方を 1 つ持つ: 押す（press）・押す・守り（guard）・選ぶ（choice。理由は ブラウザ・パソコン・画面のキー・違い）。
- 画面の答え方: そのキーボードに組が無い → 出さない。指の端末でキーをまだ見ていない → 選ぶ。表が押す・押す・守りで、この端末で届かなかった組でない → 押す。それ以外 → 選ぶ。
- 選ぶだけの組: ブラウザが先に取る組（タブ・窓）、パソコンが先に取る組（窓の切り替え・画面の写し・画面のロックなど）、この画面で使うキー（Tab・Shift+Tab・Esc）、アプリやブラウザで組が違う組。押す問いの正解に Tab・Esc・⊞・Fn を使わない。
- どの問いにも「わからない」。押す問いにはいつも「選んで答える」（Esc でも移る）。全画面のキーボードロックは使わない。

## 4. キーの読み方（`readCombo(e, layout)`・`judge(item, layout, combo, nth)`）

- 受けるのは押す枠に焦点がある間だけ。document 全体では聞かない（例外は指の端末で物理キーを 1 回見る見張り。判定はしない）。
- 判定は trusted な keydown の 1 回。keyup は待たない。repeat は数えない。
- 修飾は事件の旗（ctrlKey・altKey・shiftKey・metaKey）でちょうど一致。Ctrl+Shift+C は Ctrl+C の正解にしない。
- AltGr: Ctrl のキーボードでは、`getModifierState("AltGraph")` が真で ctrlKey と altKey が両方立ち metaKey が無いときだけ AltGr と読む（Ctrl+Alt にしない。どの項目の正解にもならない）。⌘ のキーボードでは AltGraph の旗を見ない（⌥ を押している間 AltGraph を真にするエンジンがあるため。altKey を ⌥ と読む）。
- 主のキー（上から順に当てる）:
  1. 英字: key が a〜z なら key（小文字にする）。そうでなければ code の KeyA〜KeyZ（⌥ の作る字・Process でも位置で読む）。
  2. 数字: code の Digit0〜9・Numpad0〜9。
  3. + と -（code を先に読む）: code Minus・NumpadSubtract → -（日本語の並びの Shift+- は key が「=」でも -）。code NumpadAdd → +。code Semicolon で Ctrl か ⌘ があり key が「;」「+」→ +（日本語の並びの ; + のキー。英語の並びの Ctrl+; も + と読む。ほかの項目の組でないので誤りの数え方は生まない、と決めた甘さ）。code Equal → key が「=」「+」のときだけ +（英語の並び。日本語の並びの ^ のキーは + にしない）。key が Process なら判定しない。code が空のときだけ key の「+」「=」「-」「_」で読む。
  4. ほかの記号は key を先に読む。key が Process・Dead・Unidentified か、⌥ で変わった字（ASCII の外）のときだけ code で読む（日本語の並びの [ は code が BracketRight なので、code だけで読まない）。
  5. 名前のあるキー（矢印・Home・End・PageUp・PageDown・Insert・F1〜F12・Backspace・Space）は key。⌘ のキーボードの delete は key が Backspace。
- 日本語入力: isComposing・keyCode 229・key Process で修飾が無い → 判定しない。「日本語入力をオフにしてから押す。」を出す。修飾がある → 上の順で読む（英字と数字は code。読めない記号は判定しない）。
- 修飾の無い Enter は答えにしない。修飾だけの keydown も答えにしない。

## 5. 止めるキー（`shouldCancel(e)`）

- 押す枠では、Ctrl・⌘・Alt・⌥ のつく keydown、F1〜F12、Space・矢印・Home・End・PageUp・PageDown・Insert・Backspace を preventDefault で止める。答えを待つ間も、答えた後も（repeat の keydown も止める）。字だけのキーは止めない。
- 答えると焦点は「次へ」へ移る。そのあとも `#scPlay` の中では、Ctrl・⌘・Alt・⌥ のつく keydown と F1〜F12 を止める（押し続けの repeat も、離してもう一度押した組も。コピー・貼り付け・全部を選ぶ・印刷・保存などを本当に動かさない）。修飾の無い Space・矢印などは、repeat と、答えたキーを離すまで（答えて 300 ms まで）だけ止める（その後のボタンの Space と矢印のスクロールはいつもどおり）。
- Tab・Shift+Tab・Esc は止めない。Tab で枠を出られる。Esc は選ぶ答え方へ移る（答えた後は「次へ」と同じ）。

## 6. 届かなかった組（`createMissWatcher()`）

- 見張りが立つのは、押す問いで、修飾の keydown だけが来て主のキーが来ていない・いま押している修飾の組がその項目の正解のどれかの修飾の組とちょうど同じ・1.5 秒以内に枠の焦点が外れたかページが隠れた、の全部がそろうとき。Ctrl+C の問いで Alt だけ（窓の切り替え）では立たない。
- 1 回目（このページを開いてから、その組で初めて）: その問いだけを選ぶ問いに替え、「押せなかったようだ。この問いは選んで答える。」と「もう一度押す」（押す枠に戻す）を出す。端末の鍵には書かない（ページの中のメモで 1 回と数える）。
- 2 回目（同じページで同じ組）: 「ブラウザかパソコンが先に受け取ったようだ。この組は、この端末では選んで答える。」と言い、その組を端末の鍵の miss に覚える（キーボードごとに 40 まで）。読み込み直すと一覧の札に「選んで答える」の印が出る。一覧の上の「押して答えるに戻す」で miss を空にする。
- 見張りは、主のキーの keydown（Tab・Esc も）・修飾の keyup・次の問いで必ず解く。Shift+Tab や、修飾を離した後の Tab では覚えない。
- 理由: 窓を替えるとき（Alt+Tab・⌘Tab）も、ページには修飾の keydown と blur しか来ない。本当に先に取られたのか、窓を替えただけかは区別できないので、1 回では覚えない。

## 7. ほかの項目の組・取り違え・近い組・別の組（`afterWrong`・`ownText`）

- ほかの項目の組: 今のキーボードで、ほかの項目の正解（別の組も、選ぶ項目の見せる組と別の組の札も。例: Ctrl のキーボードの貼り付けで ⊞ + V は「それは前にコピーしたものの一覧から貼り付ける組。」）に当たる押し方 → × と数え、「それは〈その項目の短い名〉の組。」と出す（例: 「それは前のページに戻る組。」。短い名が「…下へ」のように動きの言葉で終わらないときは「…下への組。」。今の表には無い）。切り替えは聞かない。短い名は表の `short`（働きから括弧を除いた字。両向きの 2 組は向きのない名: 1 画面ずつの組は「ページを 1 画面ずつ動かす」、探した言葉の次の場所の組は「探した言葉の場所を順に移る」。Batch 93。上へ動かすキーでも合う）。回の終わりの一覧の字も同じ短い名。
- 取り違え: 上に当たらず、もう一方のキーボードの正解に合う押し方 → × と数え、「⌘ のキーボードの押し方だった。切り替える？」と「⌘ のキーボードにする」（逆は Ctrl）を出す。黙って替えない。
- 近い組（公式の頁に無いか、一部のブラウザだけの組）: 数えずに同じ問いのまま「… を使うアプリもある。ここでは … で答える。」。やり直すの Ctrl+Shift+Z（Ctrl）と ⌘Y（⌘）・アドレスバーの F6 と F4（Ctrl）・戻るの ⌘←と進むの ⌘→（⌘。公式の頁にあるが一部のブラウザだけ）。
- 別の組（公式の頁にある組。数える。表の also）: コピーの Ctrl+Insert・貼り付けの Shift+Insert（Ctrl）・1 画面ずつの PageDown と PageUp（両方。⌘ のキーボードでは Fn+↓・Fn+↑ がこれになる）。注「ほかに … でも同じ。」を出す。

## 8. 次へ（`shouldAdvance(e, R, now)`）

- 答えた後の焦点は「次へ」。押す枠に焦点があれば Enter・Space でも次へ。
- repeat の keydown では進まない（Space を少し長く押すと、答えの後に repeat が来る）。答えに使ったキーの keyup が来るまで、または答えてから 300 ms の間は、Enter・Space で進まない（どちらか早い方で解く）。
- 「次へ」のボタンは、ボタンの上で始まった Enter・Space の keydown でだけ押せる。ほかで始まった Space の keyup（押す枠で答えたキーなど）は既定の動き（click）ごと止め、印や待ちを残さない（離してすぐの Enter でも次へ進む。レビュー 2）。ボタンの上の repeat の keydown も止める（選ぶ問いを Enter で答えて押し続けても次へ進まない）。マウスと Tab はいつでも使える。

## 9. 戻る・進む・再読み込みの守り

- 段の印: 足す段の状態は `{ sdGuard: <回の id> }`。印の無い段には何もしない。
- 戻る（Alt+← / ⌘[）: その問いを出すときだけ `pushState({ sdGuard })` で同じページの段を 1 つ足す。答えを待つ間に popstate が来たら「押せた」に数えて「ブラウザが先に動いたが、押せた。」と出す。段は足し直さない。答えた・次へ・やめるとき、足した段の上にいれば `history.back()` で 1 段戻り、そのときの popstate は無視する。
- `history.back()` は history.length を減らさない。足した段は「進む」の先に残る。次の回で戻るの問いを出すと pushState がその残りを置き換えるので、何回やっても増えるのは 1 段まで。
- 残った段に着いたとき: 同じページの popstate で印のある段に着いた（進む）→ 進むの問いが答えを待っていれば「押せた」に数えて戻る。ほかは黙って戻る。別のページから戻ってきて印のある段で読み込まれた（pageshow）→ `replaceState` で印を消すだけ。
- ほかの問いでは段を足さない。ほかの問いの間のブラウザの戻るは、ふつうにページを離れる（答えるたびに保存しているので記録は消えない）。
- 進む（Alt+→ / ⌘]）: 段を足さない。ページが受け取れば判定する。残った段に動いたら数える。
- 再読み込み（F5・Ctrl+R / ⌘R）: その問いの間だけ、今の段の状態に印 `{ id, layout, at, first }` を置く（replaceState。保存の鍵も sessionStorage も増やさない。first = 回の中の最初の答えか）。読み込み直した頭で、ナビゲーションの種類が reload で印が 2 分以内なら「読み込み直した。さっきの問い（ページを読み込み直す）は押せた。」と出して印を消す。記録するのは first が真のときだけ（回の中の 2 回目の出題では記録しない。§10）。答えたら印を消す。

## 13. 保存の鍵と領域

| 鍵 | 種類 | 中身 | バックアップ・書き出し |
|---|---|---|---|
| `spelldash_shortcuts` | 人ごと（既定のまま。`sd2.<領域>.shortcuts`） | `{ v: 1, it: { "<id>@<ctrl｜cmd>": { s: 1｜2, d: <日番号>, at: <ms>, how: "p"｜"c" } } }`。s が無ければ これから。d はあやふやの数えた日 | 入る |

- 読めない値は空として読む。上書きするのは答えたときだけ（キーボードの選びは選んだときだけ）。
- 書く直前に読み直し、その答え（端末の鍵は変えた欄）だけを替えて書く（`recordAnswer`・`updateDevice`）。同じ端末の 2 つのタブで練習しても、ほかのタブの答えと届かなかった組を消さない。

- 同期しない（別の端末へはバックアップで移す）。練習のページは、storage の知らせ（鍵 `spelldash_shortcuts`・`spelldash_shortcut_device` と null。人ごとの鍵の知らせは js/areaGuard.js が元の名前にして届ける）・戻るでページを残して開き直したとき（pageshow の persisted）・タブに戻ったとき（visibilitychange）に記録と端末の設定を読み直し、一覧を出している間は描き直す（開いた詳しい欄はそのまま、焦点のあった札に焦点を戻す）。回の始めにも読み直す（ほかのタブで覚えた組を出さない）。回の途中の問いは替えない。Batch 93。学習状況の 1 行も聞いて描き直す（§1）。保存の形は変えていない（古いタブも新しいタブの書いた物を読める）。

## 14. 指の端末・アプリ

- 指の端末（`isTouchDevice`）で、このページを開いてからキーをまだ見ていない → 全部の問いを選ぶ問いにする（押すと困る組も答え方の行は「選んで答える。」だけで、「押さずに選ぶ」の行を出さない。Batch 93）。一覧の上に「キーボードが無い端末では、選んで答える。キーボードをつなぐと、押して答えられる。」。開くたびに出す。
- 物理キーの trusted な keydown（物理の code・入力欄の外・日本語入力でない）が 1 回来たら、「キーボードがつながった。押して答えられる。」と言い、次の問いから押す問いを出す（今の問いは替えない）。
- 「キーボードを見た」はページの中のメモだけに持つ。端末の鍵に書かない。キーボードを外したタブレットが押す問いに閉じ込められない。キーボードをつないだまま使う人は、開くたびに何かのキーを 1 回押す（選ぶ問いの数字のキー 1〜4 でもよい）。

## 15. キーボードだけの人・読み上げの人

- 閉じ込めない: Tab・Shift+Tab・Esc を止めない。ブラウザの戻るを足し直しで止めない（§9）。Shift+Tab で枠を出ても、記録や答え方を変えない。読み上げの閲覧の形がキーを先に取っても、同じ画面の「選んで答える」でいつも答えられる。
- 選択肢のボタンの読み上げは「1. コントロール と C」。記号は「コマンド」「オプション」「コントロール」「シフト」「ロゴのキー」と読む。
- 焦点の行き先: 回の始め → 押す枠か問いの見出し。答えた後 → 次へ。回の終わり → 見出し。やめる → 練習する。どの移動も preventScroll で、ページの位置は §2.2 の見える範囲に合わせて動かす（焦点の先がヘッダーの下に隠れない）。
- 読み上げ（live の行）: 答えた後の結果（§2.3。画面の結果の行と同じ材料で 1 回）・キーボードを選ばずに「練習する」を押したときの案内（§2.1）・回の終わりの点数（§2.4）。動きを減らす設定では「動きをもう一度見る」を出さない。
- 文字 1.3 倍でも札は折り返す（キーの札は 1 つの単位で折り返さない）。

## 17. 残る危険

1. 自動のキーでは「本番でページに届くか」を証明できない。⌘ のキーボード・ほかのエンジン・日本語入力・キーボードをつないだタブレット・アプリの中は人の手で確かめていない。守りは §6 と、いつもある「選んで答える」。
2. ⌘1〜8・⌘[・⌘R・⌘L などを、ブラウザ s が止めさせるか未確認。止められずにページを離れても、答えるたびに保存しているので記録は消えない。
3. 保存（Ctrl+S・⌘S）を止められるか未確認。止められなければ保存の窓が出るだけ。
4. 拡大を止め損ねると、拡大がサイトに残る。「表示の大きさを元に戻す（Ctrl+0）」の問いで戻せる（注に書く）。
5. 戻るの守りは、その問いの間のマウスの戻るも「押せた」と数えうる（小さい）。
6. 4 つ目のブラウザの公式の頁は読めていない。読めた頁の組だけを正解にした。
7. 公式の組は版で変わる。年に 1 回、公式の頁で見直す（docs/FOUNDER_TODO.md）。
8. この機能は名前を呼び込む。単体のハッシュの一覧（会社・製品・OS・ブラウザ・言語の名前とカタカナ）が新しいファイルを見張る。
9. 窓を替えた（Alt+Tab・⌘Tab）とき、修飾が正解と同じなら、その 1 問だけ選ぶ形になる（記録しない。「もう一度押す」で戻れる）。本当に先に取られた組は、同じページで 2 回目に覚える。
10. キーボードをつないだタブレットでは、開くたびに 1 回キーを押すまで選ぶ問い（§14）。
11. ⌘ のキーボードの日本語の並びの A の左のキーは、字で確かめられていない（§12）。
12. （Batch 93 で直した）キーボードの絵の字は、狭い幅では寄せた絵で 11.6px 以上、PC の幅の全体の絵で 11.55px 以上（前は 390 以下で 4.4〜6.1px）。寄せた絵はコンテナ問い合わせで出すので、それを知らない古いエンジンでは前と同じ全体の絵だけになる（悪くはならない）。
13. 英語の並びの Ctrl+; も「大きく」の正解に数える（§4。ほかの項目の組ではない）。
14. 画面の位置（§2.2）は、ヘッダーが上に貼りつくことを前提にヘッダーの下端から測る。ヘッダーの形を変えたら 92.1 の (15) で確かめる。
15. 600×450（200% の拡大）では答えた直後に「次へ」が下にはみ出す（焦点はあり Enter で進める）。320×568 では前と後の絵が折り目の下にはみ出し、初めての人の案内の 1 行の分のずれ（CLS 0.12）が残る（docs/BACKLOG.md の Batch 93 の残り）。
16. 寄せた絵・画面の位置・読み上げは、本物の電話と本物の読み上げの道具では確かめていない（自動の検査と測りだけ）。
