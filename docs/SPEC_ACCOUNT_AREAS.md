## 1. 保存の形

### 1.1 領域と鍵

- 領域 id: `guest` か `u:<user id>`。
- 人の記録の鍵: `sd2.<領域>.<名前>`（例 `sd2.guest.word_stats`）。コードは今までどおり `spelldash_<名前>` で読み書きし、見張りが読み替える。
- 人の記録 = `spelldash_` の鍵のうち、次を除く全部（後から足した鍵も既定で人ごと。単体 U1 が一覧を固定する）:
  - 端末の設定 13 個: theme・audio・osk・after_correct・list_compact・setup_open・stats_tab・trend_range・weak_only・installed・onboarded・typing_kind・typing_game_course。
  - 端末の計測 10 個: device_id・funnel_first・funnel_paid・funnel_paid_send・funnel_queue・funnel_sent・funnel_tgame・funnel_typing・billing_open・pro_intent。
  - `spelldash_test_*`。
  - schema_version は人ごと（人ごとに移行の段が違いうるため）。
- 端末の印（`spelldash_` で始めない。旧いコードが触れない）:
  - `sd2.area` = `"<領域>#<世代>"`。切り替えのたびに世代 +1。
  - `sd2.index` = `{ <領域>: { at: "ls" | "idb:<id>", lastUsedAt } }`。各領域の本物の置き場所。
  - `sd2.migrated` = `{ at, fromSchema, legacyId, area }`。消さない。`sd2.migrating` は移行の途中だけ。
  - `sd2.switch` = `{ id, op, from, to, phase: "drain" | "swap", at }`。切り替えの途中だけ。
  - `sd2.decision` = 「移す？」の最初に確定した答え（§5）。
  - sessionStorage（タブごと）: `sd2.tabgen`（このタブが最後に見た印）・`sd2.intent`（切り替えの画面への頼み）・`sd2.notice`（戻ったページの知らせ）・`sd2.retry`（復旧の画面の「もう一度」から開いた印。読んだら消す）。
- 認証のセッションの鍵も世代を分ける: 新しい鍵 `sd2.auth`（js/supabase.js の storageKey。知らせの channel とロックの名前も別になる）。旧い鍵 `sb-<ref>-auth-token` は移行で新しい鍵へ移して消す。認証の部品の版は 2.118.0 に固定。部品には置き場（getItem・setItem・removeItem はいつも見張りが包んだ localStorage）を渡す。書けなければ例外（ログインの失敗として返す。セッションをメモリーだけに置かない）。

### 1.2 置き場所の決まり（不変条件）

- localStorage に人の記録を置くのは、いつも 1 人（今の領域）だけ。別の領域を localStorage に重ねて展開しない。
- 使っていない人は IndexedDB（DB `spelldash-areas`）の `areas` に 1 人 1 件 `{ area, id, keys, savedAt, schema, sum }`。
- `sd2.index` が指す方だけが本物。写して読み直して確かめてから index を替え、index を替えてから元を消す。
- 書くのは durability strict。新しいトランザクションで読み直し、鍵ごと・id・要約を比べる（`putVerified`）。

### 1.3 保存先ごとの扱い（必須修正 2）

| もの | IndexedDB | localStorage |
|---|---|---|
| 今の人の記録 | 置かない（切り替えのときの写しは、index が指さない古い写しとして残りうる。読まない） | `sd2.<今の領域>.*` |
| 使っていない人の記録 | `areas` に 1 人 1 件。期限なし。自動で消さない | 置かない（退避を確かめた後に消す） |
| 移行の前の旧いデータ（`spelldash_*` の人の記録の全部） | `legacy` に 1 件。期限なし。自動で消さない。同じ中身で確かめた legacy があれば使い回す | 移行を確かめた後に本体を消す。残すのは小さい印 `sd2.migrated` |
| 移行の後に旧いコードのタブが旧い鍵へ書いた値 | `orphans` に写して確かめる（area の欄なし）。期限なし | 写しを確かめた後に消す |
| 切り替えの後に、見え方の古いタブが退避した領域の鍵へ書いた値 | `orphans` に領域つき（`{ id, savedAt, area, keys, sum }`）で写して確かめる。期限なし。index の写しと同じ値は写さずに消す | 写しを確かめた後に消す |
| ログイン・ログアウトの前の予行の写し | `areas` の `pre:<領域>`。確かめた後に消す（§4） | 元は替えない |
| 復元の前の今の記録 | `prerestore` に写す。期限なし | 復元の中身で上書きする |
| 旧い認証のセッション `sb-<ref>-auth-token` | 置かない | 新しい鍵へ移した後に消す。移行の後に書かれたら写さずにすぐ消す |

- 「消す」は localStorage から外すこと。IndexedDB の写しは、利用者の明示の確認なしには消さない（消す画面は作っていない。§7 (g)）。area の無い orphans は元の持ち主へ 1 回だけ取り込み、area 付きは自動で移し直さない（§6・§11）。

## 2. 見張り（js/areaGuard.js）

- 全ページの `<head>` の最初の script。同期の classic script（module にしない）。後ろの 1 文 `window.SpellDashArea||(…)` は、見張りが読めなかったとき（取れない・壊れた）にページを止めて切り替えの画面へ移す（共用の場所で動かさない）。Battle・タイピングの 3 ページは 見張り → 入口の門 → ほかの script と CSS の順。admin.html にも付ける。
- Storage.prototype の getItem・setItem・removeItem を包む（this が localStorage のときだけ）。人の記録の鍵をページの領域の鍵に読み替える。sessionStorage は包まない。
- 使い方の全数調べ（getItem・setItem・removeItem・clear・key・length・storage イベント・`localStorage.foo`・`localStorage["foo"]`・`Object.keys`／for…in／展開・別名）: 使っている形は全部対象にした。
  - getItem・setItem・removeItem と別名: 包んだ口を通る。
  - key・length（js/backup.js・js/staticHeader.js）: 領域を知る口 `SpellDashArea.keys()`・`signedIn()` に書き替えた。
  - storage イベント: 今の領域の物理の鍵の知らせを止め、元の名前の StorageEvent に作り直して届ける。ほかの領域・旧い場所・印の知らせは届けない。
  - clear・プロパティの形・`Object.keys(localStorage)` などは使っていない（単体 U1 が、ファイルごとの一覧と別名の先まで固定する。新しく使うと落ちる）。
- 書くたび（setItem・removeItem）に、(1) `sd2.area` がページを開いたときと同じ、(2) `sd2.switch` が swap の段でない、(3) 今のセッションの人（`sd2.auth` を読む。同じタブの認証の書き込みと、ほかのタブの storage イベントで覚え直す）がページの領域の人、を確かめる。違えば書かずに InvalidStateError（呼び手の保存の失敗の道。中心の学習は「保存できませんでした」）。ページは切り替えの画面へ移す。ほかのタブで別の人がログインした後の、このタブの閉じる前の書きかけ（pagehide）も断る（その人の領域の鍵なので混ざらない。書きかけは失われる）。
- 頭で止める（`window.stop()` → `location.replace("/switch.html#back=…")`。戻り先は # の後ろに置き、サーバーと Service Worker の保存の鍵に送らない）: 移行の前・`sd2.switch` か `sd2.migrating` がある・印が読めない・ページの領域 ≠ セッションの領域・`sd2.index[領域].at` ≠ `"ls"`。
- 初めての端末（人の記録・旧い認証の鍵・`sd2.*` のどれも無い）は、その場でゲストの領域の印を書く（移すものが無い移行。切り替えの画面を通らない）。
- 自分の確かめ: 読み込みのたびに、包んだ口で書いて生の口で読む。包めない・包んだ口が使われない・確かめが合わない・Web Locks か IndexedDB が無いブラウザでは、共用の場所へ戻さず、ページを止めて「このブラウザでは記録を安全に分けられない」と「記録を書き出す」を出す（人の記録の書き込みは全部断る）。満杯の端末（確かめの書き込みが容量で入らない）は止めない（読めて、書くと容量の例外）。localStorage そのものが使えない端末（読むと例外）は止めない（何も残らないので混ざらない。同期はしない）。
- sessionStorage の `sd2.tabgen` が今の印と違えば、同期の印 4 つを消す。
- ページの間、共有のロック `spelldash-page` を持つ。pageshow（persisted）・visibilitychange（visible）・focus で確かめ直す。
- 旧い場所の片付け: 移行の後、旧い認証の鍵（-user・-code-verifier も）は頭と storage の知らせでその場で消す。旧い場所の人の記録の鍵と、退避した領域の鍵へ書かれた値は、知らせを受けたらすぐ（頭で見つけたら手の空いたときに）orphans へ写して確かめてから消す（排他のロックが空いているときだけ。切り替え・移行の途中は何もしない）。
- 新しい sw.js の問い合わせ（`sd2-ping`）に答える。
- module から使う口: `window.SpellDashArea`（area・gen・marker・authKey・isPersonKey・stillMine()・canWrite()・userId()・signedIn()・keys()・leave()）と `window.SpellDashAreaKeys`（鍵の決まり。切り替えの画面と単体も使う）。

## 3. 切り替え（switch.html・js/areaSwitch.js）

- switch.html は学習の部品を読まない（noindex）。見張りは `data-switch` で読み、包まない。部品が読めない（オフライン）ときは、小さい classic の script が復旧の画面（「通信できないため、切り替えの画面の部品を読めなかった。つながってから「もう一度」を押す。」）を出す。部品と CSS は Service Worker が先読みする。
- 排他のロック `spelldash-area-switch` を持つタブだけが、直し → 移行 → 旧い場所の片付け → 今のセッションの領域への切り替え、を順にする。
- 「元」は印でなく、index が ls を指す領域で決める（印を替える前に落ちた形では、印と index が食い違う）。
- 手順（F → T）:
  1. `sd2.switch` = `{ id, op, from F, to T, phase: "drain" }`。ほかのタブは知らせで切り替えの画面へ移る。入らなければ何も替えずに止める（理由 quota）。
  2. `spelldash-page` の持ち主が 0 になるのを最大 3 秒 + 300ms 待つ。
  3. phase = `"swap"`。見え方が今のタブ（知らせを受け取れたタブ）は、ここから人の記録を書けない。確認の窓・長い処理の間のタブは古い印を読んで書けてしまう。その書き込みは退避した領域の残りとして片付ける（§1.3。片付けは切り替えの画面の毎回・戻り先のページの頭・ほかのタブの知らせのたび）。
  4. F を IndexedDB の `areas` に写し、読み直して比べる。**失敗したら止める**: `sd2.switch` を消し、F は localStorage のまま、`sd2.area`・index は替えない（§4）。
  5. 切り替え先 T の写しを読んで確かめる（index の id と要約）。T の領域の localStorage の残りを orphans へ写す。どちらもできなければ止める（理由 target・quota・evacuate）。ログアウトなら、その後に `signOut({ scope: "local" })` と、セッションが消えたことの確かめ（§5）。
  6. F が写しと同じかを確かめてから（違えば止める・F は localStorage のまま）、`sd2.index[F]` = `idb:<id>` → F の鍵を localStorage から消す。
  7. T の残りをもう一度片付け、T が IndexedDB にあれば localStorage に全部書く。**容量で書けなければ**: この書き込みが替えた鍵だけを前の形に戻し（前に無かった鍵は消す・前からあった鍵は前の値に戻す）、T は IndexedDB に残し、F を写しから書き戻して（遅れて書かれた F の値は重ねる）`sd2.index[F]` = ls・T の index も前に戻す。`sd2.area` は替えない。復旧の画面で容量不足を知らせる（§4）。
  8. `sd2.index[T]` = ls（新しい T なら作る）。
  9. `sd2.area` = T#世代+1（1 回の書き込み）。`sd2.switch` を消す。戻り先へ移る。
- 1・3・6・8・9 とその間のどの段も、容量で入らなければ理由は容量、ほかの例外は退避の失敗で、同じ止め方（途中の印を消す・元を localStorage に戻す）を通る。
- 直し（`sd2.switch` が残っていた。タブを閉じた・落ちた）: index が指す方だけが本物。index が idb を指す領域の localStorage の残りは、写しと同じなら消し、違う値は orphans へ写してから消す（写せなければ途中の印を残して止める）。index が ls を指す領域はそのまま。そのうえで最初からやり直す。古い写しは index が指さないので戻さない。
- 前の切り替えが手順 6 の後で落ち、localStorage に領域が 1 つも無いときは、index が指す確かめた写しから F を書き戻して止める。IndexedDB を開けずに書き戻せないときは、記録を失わず（写しは残る）、学習・保存・同期は止めたまま、書き出しは断る。開けるようになれば「もう一度」で戻る。
- 凍ったタブ（条件つき承認）: 2 の待ちで残っても進める。戻ったら頭の見張りで切り替えの画面へ移る。旧いコードのタブは §6。
- persist() は、移行と切り替えの退避で、まだ永続でなければ 1 回頼む（§7 (f)）。

## 4. 退避できないとき・認証が先に変わったとき（必須修正 1）

- **予行（先に確かめる）**: ログインのリンクを送る前・外部のログインへ移る前・ログアウトの前に、今の領域を IndexedDB の `areas` に `pre:<領域>` で写して読み直す（本物の写しは触らない）。できなければ、リンクを送らない・移らない・ログアウトしない。文「この端末に記録を安全に保存できなかったため、切り替えられません。」と、ほかのタブを閉じる・端末の空きを作る・書き出す・もう一度、の案内。
  - 予行の写しは確かめた後に消す（消せなければ予行は失敗。空きを確かめたことにならない）。予行は元（localStorage の今の領域）を替えないので、消す直前・直後でタブが落ちても A は 1 字も違わない。残った予行の写しは本物の写しとして読まず、次の予行が消す（§0.3 の 3）。
  - 予行が確かめるのは今の領域の 1 人分。「移す？」の「はい」は 2 人分を書くので、1.5 人分しか空きの無い端末では手順が容量で止まり復旧の画面になる（記録は失わない。§11）。
  - 予行が通っても切り替えの画面の退避が失敗すれば、signOut せずに元のページへ戻して同じ文を出す。
- ログアウト: 退避と切り替え先の確かめ（§3 の 4・5）の後に signOut。どれかが失敗したら、元の人の記録とログインをそのまま残し、元のページへ戻す（知らせ logout-blocked）。
- **認証が先に変わった**（リンクでほかのアカウントに入った・トークンが切れた・ほかのタブで替わった）のに退避や展開ができない: 学習・同期・保存を全部止め、復旧の画面に移す（どのページも頭の見張りで切り替えの画面に来るので、学習の部品は動かない）。元の領域は localStorage のまま失わない。別の領域を重ねて展開しない。
- 復旧の画面:
  - 文「この端末に記録を安全に保存できなかったため、切り替えられません。」。どの段の書き込みでも容量で入らなければ「この端末の保存の空きが足りない。」を足す。
  - 「記録はこの端末に残っている。」は、index が指す写し（移行の途中は legacy も）を全部読めて確かめられたときだけ。読めなければ「この端末にある記録の控えの一部を読めなかった。」。「学習・保存・同期は止めた。」はいつも。
  - 案内: ほかの SpellDash のタブを閉じる・端末の空きを作る・プライベートの窓では開かない・書き出してからもう一度。
  - 「記録を書き出す」: localStorage の今の領域（無ければ index が指す確かめた写し。移行の途中は確かめた legacy）。持ち主の値（§5）つき。移行の前は旧い記録で持ち主を付けない。バックアップと同じ鍵を除く（§5）。写しも読めなければ書き出さない（「記録の控えを読めなかったため、書き出せなかった。」）。
  - 「移す？」の答えが決まっていれば、その答えを 1 行で出す。「もう一度」はその答えのまま続ける。
- IndexedDB が使えないブラウザ: 移行と切り替えをしない（共用に戻さない。§2）。

## 5. ログイン・ログアウト・同期・バックアップ

- **ページと人**（js/auth.js `areaFit`）: 部品の答えたセッションとページの領域を比べる。fits（同じ人・stillMine）なら同期と Pro の状態の更新をする。leave（ほかの人・ゲストのページにセッション・stillMine でない）なら同期も更新もせずに切り替えの画面へ。unknown（部品は「セッション無し」と答えたが保存のセッション `sd2.auth` はある。部品が読めない・オフラインで期限切れ）なら移らず、同期もしない（行き来しない）。部品がセッションを取り戻したら、その知らせで始める。
- **ログイン**: セッションの人が替わったら、同期の前にどのタブも切り替えの画面へ。ログインから戻った印（sessionStorage の `spelldash_login_return`。URL に戻りのトークンがあれば読み込みの頭で残す）は、ページがこの人の領域にそろうまで消さない（加入の途中ならログインの後に加入画面へ戻る）。
- **この端末で初めて A に入り、ゲストに記録がある**（元がゲストで localStorage にあり、A が index に無く、ゲストに記録がある）: 「ゲストで学んだ記録を、このアカウントに移す？」を 1 回たずねる。
  - はい = ゲストの写しを確かめてから、持ち主の鍵・xp_synced・xp_write・logout_at・learn_filled を消して A の領域へ移し、ゲストを index から外す。落ちた後は続きを直す。
  - いいえ = 移さない。ログインは続ける。ゲストは IndexedDB へ退避し、A は空の領域からクラウドを取り込む。
  - 問いは排他のロックの外で、切り替えの画面を開いたどのタブにも出る。答えたタブはロックの中で、まだ同じ切り替え先への問いが要るかを確かめ、切り替えより先に答えを `sd2.decision` = `{ id, from: "guest", to, answer, at, gen }` に残す。ロックを後から取ったタブは残った答えを使う（自分のタブで押した答えは捨てる。同じ元・切り替え先・世代の答えだけ。違えば消してたずね直す）。切り替えが済んだら消す。たずねる間にセッションが替われば、今のセッションでたずね直す（§0.3 の 2）。
  - 決まった答えの切り替えが失敗したら、答えと理由（failed）を残す。復旧の画面の「もう一度」でだけ同じ答えでやり直す。それまでは、空きができていても、どのタブも同じ理由で止まる。
- **A の領域がこの端末にある**（index に A の行がある。localStorage でも写しでも）: たずねずに戻す。ゲストはゲストに残る。ログアウトの後に未ログインで学んだ答えはゲストの領域に入り、A に入り直しても混ぜない。
- **移行の前の記録の「足す」**: 前の版のログアウトの時刻の印（`spelldash_logout_at`）が残っている旧い形の記録だけ、同じアカウントで入り直したときに「この端末の記録を、このアカウントの記録に足す。別の人の記録なら、キャンセルしてログインをやめる。」をたずねる。キャンセルは切り替えの画面のログアウト（scope local。文「ログインをやめた。記録はこの端末に残る。」）。領域のログアウトはこの印を書かない。
- **ログアウト**: 予行（§4）の後に切り替えの画面で、退避 → 切り替え先（ゲスト）の写しの確かめ → scope local の signOut と確かめ → 元を消す → ゲストを展開 → 印を替える。文「ログアウトした。記録はこのアカウントに残る。」。失敗なら「ログアウトできなかった。記録とログインはそのまま。通信がつながってから、もう一度。」か、退避の失敗の文。保存の無い端末だけ、その場で scope local の signOut。
- **同期**（js/sync.js）: 取り込み・送信・ユーザーの品の同期の頭と、送るたび（then の時）に、ページの領域が `u:<セッションの人>` で stillMine() かを確かめる。違えば送らない（「記録の持ち主が替わったため送らなかった。」）。前の「この端末には別のアカウントの記録がある。消して、このアカウントの記録に置き換える」の確認と、端末の記録を消す道（`clearLocalRecords` の呼び出し）は無くした。領域の持ち主の鍵が別の人（壊れた記録のときだけ）なら、消さず・たずねず・同期しない。
- **送る直前の確かめ**（js/supabase.js）: 表への要求（`/rest/v1/`）は、トークンの人の領域がページの領域で stillMine() のときだけ送る。違えば送らずに 409（`SD2_AREA`）を返す。表への要求には世代の印 `X-Client-Info: spelldash/2 supabase-js-web/2.118.0` を付ける（印の無い書き込みを断るサーバー側の門は docs/SQL_CLIENT_GATE.md の案・未実行）。
- **支払いの完了の送り待ち**（端末の鍵 `spelldash_funnel_paid_send`）: 値は `{ day, user: 払った人 }`。払った人のログインのときだけ送り、送る直前にも今のセッションの人を確かめる。前の形（日付だけ）は Pro の人のページでだけ、その人の物として送る。
- **バックアップ**（js/backup.js・js/profileView.js）:
  - 書き出しは今の領域だけ。持ち主の値 owner = `{ kind: "guest" }` か `{ kind: "account", tag }`。tag = SHA-256("spelldash-backup-owner-v1:" + user id) の頭 32 字。端末ごとの乱数を使わないので、同じアカウントなら別の端末でも同じ値。生の user id は書かない。
  - 書き出さない鍵: 持ち主の鍵・同期の印・送信待ち・ログアウトの時刻・初めの埋めの印・このタブの同期の印・タイピングの好み 2 つ・Pro の状態の控え（spelldash_plan）・支払いの印（spelldash_funnel_paid）。送信待ちのご意見の行の user_id も外す（戻すときも外す）。決まりは見張りと js/backup.js で 1 つ（単体が同じ値を返すかを見る）。
  - 戻すのは同じ持ち主の領域だけ（tag を今の人から作って比べる）。違えば止める（別のアカウント・アカウントのファイルをゲストへ・ゲストのファイルをアカウントへ、それぞれの文）。切り替えの途中なら戻さない。
  - 持ち主の無い古いファイル: 覚えた語数（戻した後の学習状況と同じ数え方）・答えた語数・最後に学んだ日と、入れる先を見せ、確認してから今の領域へ。
  - 戻すのは上書き。前に警告。今の領域を IndexedDB の `prerestore` に写して確かめる。写せなければ戻さない。
- **確認用の配信**（§0.4 の決定 7。js/previewHost.js）: 確認用の配信ではログインの入口を隠し、認証の部品もクラウドも呼ばない（同期もしない）。バックアップの読み込み（今の記録の置き換え）も止める（書き出しはできる）。記録はその配信を開いた端末にだけ残る。

## 6. 旧コードのタブ

- 守りの本体（sw.js に頼らない）:
  1. 人の記録の鍵を新しくする（`sd2.`）。旧いコードは新しい鍵を読まない・書かない。新しいコードは移行の後に旧い鍵を読まない（片付けて orphans へ）。
  2. 認証のセッションの鍵を新しくする（§1.1）。旧いタブは旧い鍵のセッションしか持てない。移行で旧い鍵を消すので、旧いタブはセッションを失う（送れない）か、自分のトークンの更新で旧い鍵を書き戻しても A のまま（B にはならない）。古い部品（2.107.0 より前）のその書き戻しは、開いている新しいコードのタブの見張りがその場で消す（数ミリ秒。§2。消さないと、旧いタブが移行の後の空の値で A のクラウドの記録を後ろへ戻しうる）。B のセッションは新しい鍵にだけあり、旧いタブの部品はそれを読まない（知らせの channel も別）。だから旧いタブは B として送れない。
  3. 旧い場所の `spelldash_owner` に「移した」の印 `sd2-moved` を書く（旧いコードの同期は持ち主の違いとして確認を出し、黙って足さない）。
- 補助（根拠にしない）: sw.js の版を上げ（spelldash-v8）、有効になったら、問い合わせに 1.5 秒答えない窓を読み直させる（URL の # の後ろは外す。activate を待たせない）。
- **証明**（tests/oldtab・CI のジョブ oldtab）: 直前の本番 0507672 のコードを同じ origin で開いた旧いタブ（凍結・通信断・見えたまま・裏・Service Worker なし）と新しいコードのタブで、創業者の 5 段（A で旧い版を開く → 別のタブを新しい版へ → 新しい版で B にログイン → 旧いタブを戻して答え・同期・トークンの更新 → 閉じる）を流す。認証の部品は本物（固定の版。検査の時に登録所から取って固定の値で確かめる。リポジトリには入れない）、受け口はにせ物。B の名前の書き込みは B のクラウドの初めの値と列ごとに比べ、旧いコードのタブが B として動いたら漏れ。A の記録が後ろへ戻ったら LOSS。6 段目で A へ戻り、旧いタブの学習が A に 1 回だけ入るか（§0.3 の 1）を見る。
- **取り込み**（js/oldTabImport.js・js/areaSwitch.js）: area の無い orphans を、移行の印が指す元の持ち主の領域を展開するときだけ読む。回数は今の A の値へ足し、最後の日時は新しい方、語は A の送信待ちへ。Study の公開語だけ 3 状態を動かす。自力正解を証明できない正解は覚えたにせず、誤答・ヒントと同じくあやふや。非公開語と Challenge・Daily は回数と日時だけ。XP・連続日数は触らない。取り込んだ orphan id は A の `spelldash_oldtab_imported` に同じ展開で書き、2 回目は飛ばす。B・ゲストには入れない。
- 結果（統合の木）: 漏れ 0・後退 0・B とゲストの領域に旧いタブの語 0（Service Worker あり・なし、古い部品 2.105.0 の書き戻しの回も）。取り込みを足す前は A へ戻る段だけ NOT_IMPORTED。分離の前の木（09077e1）は漏れる（A→B 60 件ほど）。守りを外した変異 3 つ（認証の鍵の分離・記録の領域の分離・旧い場所の片付け）は落ちる。取り込みを足した後の最終結果は PR の CI で確定する。

## 7. (a)〜(h) の決まり

- (a) ほかのタブは自動で切り替えの画面へ。凍ったタブがあっても止めない（§3 の 2・3）。旧いコードのタブは §6。
- (b) 退避・照合ができなければ、ログアウト・切り替えを完了しない。元の人の記録とログインを保つ。認証が先に変わったら復旧の画面（§4）。
- (c) 移行の割り当て: 持ち主の印があればその人の領域（ログインの状態によらない）。無ければ、ログイン中ならその人、未ログインならゲスト。その後、今のログインに合わせて §3 で切り替える。持ち主 A・未ログイン → A の領域へ入れて IndexedDB へ退避し、ゲストは空で始まる。
- (d) ログアウトの後はゲストの領域（初めてなら空）。文「ログアウトした。記録はこのアカウントに残る。」。privacy.html: 人ごとに分けて保存する・ログアウトしても記録はそのアカウントの写しとして端末に残る・IndexedDB の写しは自動で消さない。
- (e) 旧いタブの書き込みは orphans へ写して localStorage から消す（§1.3・§6）。A へ戻ったとき、未取り込みの id だけを A に足す。
- (f) persist() は初めて IndexedDB に写すときに頼む。断られても分ける。書けなければ成功と見せない（§2・§4）。
- (g) 削除・使えなくなったアカウントの領域は消さない。`sd2.index` の lastUsedAt。消す画面は作らない。
- (h) バックアップの持ち主（§5）。

## 8. 移行（一度だけ・何度流しても同じ。切り替えの画面でロックを持つタブだけ）

1. 旧い鍵の人の記録を全部、IndexedDB の `legacy` に写す（id を付ける）→ 読み直して比べる。同じ中身で確かめた legacy があれば使い回す。失敗 → 止める（旧い記録はそのまま。§4 の画面・書き出し）。
2. 領域を決める（§7 (c)）。
3. `sd2.migrating` = `{ legacyId }`（入らなければ容量で止める）。旧い鍵の中身を新しい鍵 `sd2.<領域>.*` へ書く。入らなければ、legacy と同じ値の旧い本体を全部消してから書き直す（中身は legacy にある）。新しい鍵を読み直して legacy と比べる（書き込みが黙って消える保存では止め、旧い本体を消さない）。
4. 旧い鍵の本体を localStorage から消す（写した値と同じ物だけ。違う値は旧いタブが後から書いた物で、片付けが orphans へ）。`spelldash_owner` に `sd2-moved`。認証のセッションを新しい鍵へ移して旧い鍵を消す（並んで入らなければ旧い鍵を先に消す）。
5. `sd2.index[領域]` = ls・`sd2.area` = 領域#1・`sd2.migrated`（`{ at, fromSchema, legacyId, area }`）を書き、`sd2.migrating` を消す。終わりの印が並んで入らなければ、途中の印を先に消して書く。
- 落ちたら: `sd2.migrating` があれば legacy（同じ id）から 3 をやり直す。途中の印を消した後に落ちた形は、「領域の印があり index がその領域を ls と指す」から終わったと分かり、終わりの印だけ書く。
- 移行の後に旧い鍵が現れたら: orphans に写して確かめてから消す（§2・§1.3）。

## 11. 公開前の確認・決めてほしいこと

- **旧タブの書き込みの取り込み**（§0.3 の 1・§0.4 の決定 6）: 実装と単体検査は済み。PR の CI で、実物の旧版 0507672 を使う全組が PASS（漏れ・後退・段の失敗・二重取り込み・不足が 0）になることを最終確認する。検査は弱めない。
- **オフラインのログアウト**: 固定した版の部品は、受け口に届かなくても、この端末のセッションを先に消してから失敗を返す（トークンが有効なとき）。今は切り替えが止まり（A は localStorage のまま・A の写しは確かめてある・2 人分を重ねない・途中の印なし）、復旧の画面を出す。次に開くとふつうの切り替えでゲストへ。記録は失わず混ざらないが、文が実際と合わない。決めてほしいこと: (a) 退避を確かめた後なら、そのままゲストへの切り替えを終え、「この端末ではログアウトした。サーバーには届かなかった。」などと出す／(b) signOut の前に受け口に届くかを確かめ、届かなければ呼ばずに「ログアウトできなかった。…」／(c) 今の動きのまま、復旧の画面の文だけ替える。
- **復旧の画面の出口**: 原因が続く（写しが消えた・壊れた・IndexedDB にずっと書けない）と、どのページを開いても復旧の画面に残る（ログインのフォームもログアウトも無い）。決めてほしいこと（どれか、または組み合わせ）: (1) 復旧の画面に「この端末だけログアウトする」を置く／(2) localStorage にある領域の人のログインのリンクだけ、切り替えの画面で読む／(3) 写しが消えた・壊れたと分かった領域を、書き出しと確かめの後に「この端末の写しは無い」として扱い、空から（アカウントはクラウドから）始める（利用者の明示の確認が要る）。どれでも「学習・同期・保存を止める」と「2 人分を localStorage に重ねない」は変えない。
- **予行の空き**: 予行は 1 人分しか確かめない（§4）。2 人分を確かめると、空きの少ない端末でログインを断ることが増える。
- **支払いの完了の重ねない印**は端末で 1 つ（サーバーの unique も user を含まない）。同じ端末・同じ日に A と B の両方が支払いを終えると、後の人の完了は送られない。替えるには SQL が要る。
- 旧いタブが B のログインの後にした学習は、B ではなく、移行で決めた元の持ち主へ戻した時に 1 回だけ入る。
- 消す画面（IndexedDB の写し・orphans・legacy）は作っていない（§7 (g)）。
