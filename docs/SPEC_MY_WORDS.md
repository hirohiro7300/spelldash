## 11. 同じ英語を何度も（Batch 82。創業者の依頼 2026-11-07「同じ単語を入れられなくなってるから、それも調整してくれ」）

創業者は「up, 〈場面〉。〈数字〉は上がる？下がる？」「down, 〈場面〉。…」の形の行（英語は up と down だけ、訳が場面の問い）をまとめて足して覚えたい。前は英語が鍵で 1 つしか入らず、2 行目からの up と down は「すでに登録」で飛ばされ、訳に「→」のある行は場面カードになっていた。

### 11.1 鍵と答えの英語

- **鍵**（保存の `en`）は語の名前: 同期の項目 `my_word:<鍵>`・墓標・選んだ印 `word:<鍵>`・カードの id `my-<鍵>`・答えの書き手（`recordMyAnswer`）・消す・移す・訳を直すは、どれも鍵で語を引く。前からの語の鍵・id・訳・状態・単語帳は 1 字も変えない（読むだけでは何も書かない）。
- その英語の最初の語は今までどおり英語の鍵（小文字。`up`）。同じ英語の 2 つ目からの語の鍵は `<英語の鍵>~<訳の印 8 桁>`（`js/myWordsCore.js myIdentityFor`。例 `up~78d1e2c6`）。「~」は英語に使えない字なので、英語の鍵と重ならない。2 つ目からの語はいつも `text`（打ったとおりの英語）を持つ。
  - 訳の印（`jaHash`）は、比べる形にした訳（`normJa`: NFKC・空白の並びは 1 つ・前後の空白を落とす）の UTF-8 の FNV-1a（32 ビット）の 16 進 8 桁。訳だけで決まる（端末・並び・時刻に依らない）ので、前からの語を共にする 2 台で同じ組を足すと同じ鍵になり、同期で 1 語にまとまる。

## 13. 単語帳を人に渡す（Batch 84）

### 13.1 渡す

- 単語帳の道具（新しい単語帳・名前を変える の並び）に「渡す」。今の決まりで渡せる語が 1 つ以上ある単語帳だけに出す（英語の語が無い単語帳と、今の決まりに合わない古い語だけの単語帳には出さない: 押しても何も起きないボタンを出さない。判定は押したときと同じ `bookShare`。読み上げの名前「「名前」を渡す」・`aria-expanded`・`aria-controls`）。押すと札「「名前」を渡す」・語の数と 1 行の説明・入る物の注意（名前と英語と訳だけ・覚えたかどうかは入らない・リンクを知っている人はだれでも見られる）。

### 13.2 code の形（`js/myWordsShare.js`。版 1）

- JSON `{"v":1,"n":"<単語帳の名前>","w":[["<英語（画面の形）>","<訳>"], ...]}` → UTF-8 → 縮める（`CompressionStream` の deflate-raw。使えるとき）→ base64url（= なし）。頭の印は縮めたら `z1.`、縮めなければ `j1.`（`CompressionStream` の無いブラウザで作ったとき）。
- 入るのは単語帳の名前と、語ごとの英語（画面に出す形。KPI は KPI のまま）と訳だけ。保存の鍵（`up~<訳の印>`）・3 状態・id・日付・単語帳の id・アカウントは入れない。
- 読み方（`decodeShare`）: `z1.`・`j1.` のほかは断る。base64url の形（使えない字・長さの余り 1・最後の字の使わないビット）を確かめる。`z1.` は縮めた物を 4 KB ずつ広げる道（`DecompressionStream`）へ渡し、広げた大きさに上限を付けて読み、超えたら読むのをやめて断る（残りの切れは渡さない）。ブラウザの広げ方は渡された 1 切れを全部広げてから読む側に渡すので、1 度に全部を渡すと上限で止めても広げすぎる（1.3 MB の code で約 1 GB を広げ、描く側の記憶が約 950 MB 増えた）。4 KB ずつなら 1 切れでも約 4 MB まで（同じ code で増えは約 13 MB・10 ms）。壊れた UTF-8 と頭の BOM を断る。JSON は `JSON.parse` だけ（eval しない）。鍵は v・n・w の 3 つだけ、v は 1、n は単語帳の名前の決まり（20 字まで）、w は 1〜1,000 個の [文字, 文字]、語は 1 語ずつ足すと同じ決まり（英語も訳も 150 字まで）で、1 つでも合わなければリンクごと断る。
- 名前と訳の字: 制御文字（U+0000〜U+001F・U+007F〜U+009F。タブと改行は先に空白 1 つになる）・組になっていないサロゲート・向きを変える制御文字（埋め込み・上書き・隔離: U+202A〜U+202E・U+2066〜U+2069）があれば断る（名前は name、訳は entry）。同期の送り先（`user_items` の payload）は NUL と組になっていないサロゲートを受け付けず、1 語でも入ると同じ送りの組の語・メモがどれも届かなくなる（リンクからは入れない。Batch 85 から、決まりは `js/myWordsCore.js` の 1 か所で、1 語ずつ足す・まとめて足す・訳を直す・単語帳の名前も同じ決まり: §14.1）。向きを変える字は名前と訳の見え方を並べ替えられるので一緒に断る。絵文字（組になったサロゲート）・全角の空白などは読める。渡す側（`bookShare`）も同じ決まりで語を選ぶ（合わない語は入れずに数える。名前が合わなければ最初の単語帳の名前）ので、作った code は必ず読める。
- 同じ鍵が 2 度ある JSON は `JSON.parse` の決まりで後の値になる（鍵が v・n・w の 3 つだけなのは変わらないので害は無い。断らない）。
- 画面は読んだ字を `textContent` だけで出す（`innerHTML` に入れない）。
- 形を変えるときは v を 2 にし、頭の印も替える（`z2.` など）。今の画面は v: 1 のほかを読まない（「このリンクは読めません」）。

## 14. 字の守りと同期の頑丈さ（Batch 85）

### 14.1 字の決まり（1 か所: `js/myWordsCore.js`）

- `UNSAFE_TEXT`: 制御文字（U+0000〜U+001F・U+007F〜U+009F）・向きを変える制御文字（埋め込み・上書き・隔離: U+202A〜U+202E・U+2066〜U+2069）・組になっていないサロゲート。`isSafeText`（決まりに合うか）・`withoutUnsafe`（その字だけを落とした形）・`visibleText`（画面に出す形: タブ・改行などの空白の字を空白にしてから、その字を落とす。タブも制御文字の範囲なので、先に空白にしないと前後の語がつながる）・`cutText`（UTF-16 の長さで切るが、絵文字などの組を半分にしない）・`UNSAFE_TEXT_ERROR`（「見えない字や壊れた字が入っています。打ち直してください」）。Batch 84 で `js/myWordsShare.js` に置いた正規表現をここへ移した（渡すリンクの振る舞いは前のまま）。

- タブ・改行（と縦タブ・改ページ・復帰）は、前からの空白の決まりで先に空白 1 つになるので断らない（まとめて足すのタブは区切り、改行は行の区切りのまま）。絵文字（組になったサロゲート）・全角の空白・幅の無い字・向きの印（U+200E・U+200F）は訳と名前に使える（英語は前からの使える字の決まりで断る）。
- 使う所（どれも `checkEnText`・`checkJaText`・`checkBookName` か `isSafeText`。何も書かない）:
  - 1 語ずつ足す（英語・訳）。焦点はその欄のまま
  - まとめて足す: その行だけ断り、「足せなかった行」に行の名前（英語と訳の頭。`visibleText` の形: タブは空白にして、見えない字は外す。頭は 24 字で、絵文字を半分にしない）と理由を言う。ほかの行は足す。断った行は貼った形のまま欄に残す（直して足し直せる）
  - 訳を直す（欄は開いたまま・焦点も欄・保存は変えない）
  - 単語帳を作る・名前を変える（焦点は名前の欄・一覧は書かない）
  - 渡すリンク（読む側も渡す側も前のまま: §13.2）・渡された語を足す（`addSharedWords`）
  - 場面カード（`addMyConcept`。古い単語帳のページと文から作る道。今は閉じた画面だけ）: 場面・答え・解説・別解。場面の欄は複数行なので、改行とタブは前のまま通す。鍵（`conceptKey`: NFKC・小文字・空白などを外した答えの 40 字）と訳（解説の頭 40 字）は `cutText` で切る: NFKC で長くなる答え（㍿ → 株式会社）や解説の 40 字目が絵文字の途中でも、組になっていないサロゲートを作らない（切る所が組の途中でなければ前と同じ鍵）。鍵も同じ決まりで確かめる（決まりに合う答えなら鍵も合う: どの字も NFKC と小文字で決まりに合わない字にならないことを全部の字で確かめた）

### 14.3 同期の送り方（`js/userItemsSync.js`）

- 送る写しの字を整える（`cleanSendValue`）: 送る行の payload の字（入れ子の物と鍵の名前も）のうち、送り先が受け付けない字（NUL と組になっていないサロゲート）だけを 1 字ずつ U+FFFD に替える。ほかの字（タブ・改行・ほかの制御文字・C1・向きを変える字）は前のまま送る（送り先は受け付ける。前の版も送っていた）。字を落とすと、見えない字だけの訳・場面・メモがほかの端末で空になって語が見えなくなり（一覧は訳の無い語を出さない）、字だけが違う 2 つの組（「り・NUL・んご」と「りんご」）が同じ組になる。1 字を 1 字に替えるので、空でない欄は空にならない。端末の保存は書き換えない。新しく入れる字は入れる道が断る（§14.1）。

- 表の読みは、1 回の答えの行に上限がある（データベースの会社の管理画面の Max Rows。既定 1,000）。前は 1 回だけ読んでいたので、1,000 語の人の `user_items`（語 1,000 行と日ごとの記録）と 1,000 語を超える学習記録（`word_progress`）は 1,000 行で切れ、届かなかった行を「クラウドに無い」と見て端末の古い値で送り返していた（ほかの端末で直した新しい訳が古い訳に戻る）。
- 今は主キーの列（`user_items` は kind と key、`word_progress` は word_id）で並べて `READ_PAGE`（1,000）行ずつ読む。最初の読みで全部の行の数（count）を聞く。次のページの頭は受け取った行の数（管理画面の上限が 1,000 より小さくても抜けない）。1 ページ目で数に届けば終わり。2 ページ目からは、数に届いても、そのページが満ちていれば（1 ページ目と同じ行の数）もう 1 ページ読み、満ちていないページか 0 行の答えで終える（数がページの行の数のちょうど倍数のときだけ、要求が 1 回増える）。`READ_PAGES_MAX`（50 ページ = 5 万行）で終わらなければ失敗。
- 読みの途中でほかの端末が、前のページの範囲に並ぶ行を足すことがある（今日の日の行・新しい学習記録）。足された行より後ろの行は 1 つずつ後ろへずれるので、数（1 ページ目の時点）に届いた所で止めると、ずれて最後のページの外に出た前からの行を読まずに済ませ、その項目を「クラウドに無い」と見て端末の古い値で送り返していた（反証の直し。単体 test-text-safe 6.11・6.12）。行は消さない（消すのは墓標）ので、満ちていないページまで読めば、前からある行はどれも 1 度は届く（同じ行が 2 度届くことはある。項目ごとに合わせるので害は無い）。読みを始めた後に足された行は届かないことがある（読む前の表を読んだのと同じ。次の同期で届く）。
- どのページの読みが落ちても、数に届く前に 0 行の答えが来ても、読み全体を失敗にする: `user_items` はその回の取り込み（合わせる・送り返す）をしない（表が無いときの 1 行〔§15.3〕は前のまま）。最初の同期（`initialSync`）は印を戻して止め、次の同期で読み直す。半分だけ読んだ行で合わせない。
- 管理画面の Max Rows は 1,000 より小さくしない（値が何でも全部読めるが、小さくすると要求の数が増える。docs/CRM.md §8・docs/FOUNDER_TODO.md B の 17）。

### 17.2 取り込み（`js/userItemsSync.js`）

- 語の行は前のとおり新しい方が勝つ。lf だけは同じ語（足した時刻 addedAt が同じ）の早い方を残す（`keepFirstLearned`。0 はどの日より早い。消して足し直した語〔addedAt が違う〕・字などの読めない lf には写さない）。

  - 端末の行が新しくて勝つ: 雲の行の早い lf を端末の語に写してから送る（送る時刻は前のまま）。

### 18.1 同じカードの 3 状態と lf（`mergeMyWordPair`）

- 両方に生きた語があり、同じカード（足した時刻 addedAt が同じか、`normJa` で同じ訳。足した時刻は両方にあるときだけ比べる）のときだけ、3 状態（`ls`・`lsd`・`lsAt`）は `lsAt` の新しい側から（`lsAt` の無い側は答えていない。同じなら勝った行のまま）、`lf` は両方の早い方（0 以上の整数だけ。0 はどの日より早い）を残す。足した時刻が違っても、同じ訳なら同じカード。
- 違うカード（足した時刻も訳も違う）には写さない（答えていない語を 覚えた にしない）。
- 雲の行が勝ち、3 状態か lf が雲の行と違う形になった語だけを「雲の行の時刻 + 1 ms」で送り返す（§17.2 と同じ時刻。2 回目の取り込みからは送らない）。端末の行が勝つ向きも、写してから送る（端末の語にも書く。写す欄が無ければ消す。送る時刻は前のまま）。

### 18.2 同じ鍵の違うカードは両方残す（`moveDifferentCards`）

- 雲の行が生きた英語の語で、端末の同じ鍵の英語の語が違うカードで、その鍵がまだ送っていない変更（送る待ちにある）ときだけ、取り込みの初め（`localItems` の前）に端末の語を新しい鍵へ移す。
- 新しい鍵: 雲に同じ組（答えの英語と訳）が別の鍵であれば、その鍵（端末にその鍵が無いときだけ。同じカードとしてまとまり、3 状態は §18.1）。無ければ `myIdentityFor`（端末の語と雲の生きた語の鍵を全部使っていると見る。`<英語の鍵>~<訳の印>`）。
- `text` が無ければ答えの英語を入れる。ほかの欄（訳・単語帳・3 状態・lf・足した時刻）はそのまま。新しい鍵に前の印の時刻を付けて送る待ちに足し、前の鍵の印と送る待ちは外す（雲の行をそのまま取り込む）。書く順は 送る待ち → 語 → 印（前の鍵を送る待ちに残したまま語だけ移すと、次の送信が前の鍵の墓標を送ってほかの端末の語を消すため）。
- 送る待ちに無い語（送ってから変えていない語）は今どおり新しい行に替える（ほかの端末で消して足し直した語を戻さない）。送ってから答え・訳の直し・移動・名前の変更で送る待ちに戻った語は、まだ送っていない語と見分けられないので移す（ほかの端末で消して違う訳で足し直した語でも、前の語が別の鍵で戻る。消える語は無い: §18.6・T20）。場面カード（kind concept）と同じ鍵の行は今のまま。消した行は §18.8・§18.10。

### 18.3 消した語の鍵を使い回さない（`js/myWords.js unsentDeletedKeys`）

### 18.8 消した語の墓標（Batch 94 の直し）

### 18.9 雲を読めなかった後は語を送らない（Batch 94 の直し）

- 同期の取り込み（`pullUserItems`）はタブの最初のページだけで動き、雲を読めなくても（表が無い・通信の失敗）同期の取り込み済みの印は付く（js/sync.js。変えていない）。前は、その後の送り（`pushSync` → `pushUserItems`）が、雲と合わせていない送る待ちの語をそのまま送り、ほかの端末の同じ鍵の違うカード（覚えた）を新しい時刻で上書きした（表を作ったときに開いていたタブ・ログインして「はい」の後の最初の読みが落ちたタブ）。
- 取り込みが読めなかったら、同期の印（`spelldash_user_items_meta`）の中に、行でない印 `unmerged` を 1 つ付ける（行の id はいつも「kind:key」なので重ならない。新しい保存の鍵は作らない）。印がある間、`pushUserItems` はマイ単語帳の語（生きた語も墓標も）を送る待ちに残す。メモ・パック・日の記録は今どおり送る。次に雲を読めた取り込み（`mergeCloudItems`）が印を外し、合わせてから送る。

### 18.10 雲の新しい墓標と、ほかの端末が見られなかった語（Batch 94 の直し）

- 雲の墓標は中身が空なので、どのカードを消したかは分からない。前は、雲の墓標がこの端末の送る待ちの語より新しいと、その語を消した。電話が自分のカード（lead=甲）を消して墓標を送った後に、パソコンがゲストのときに足して 覚えた にした同じ英語の違うカード（lead=丁）を持って「はい」すると、丁 が消えた。§18.8 の逆の向きで、乱数の 2 台の取り込みの実際に近い組（1,000 × 2）で残っていた消え（6 件・5 件）はどれもこの形だった。
- 取り込み（`mergeCloudItems`）の終わりに、雲と合わせた時刻を同期の印（`spelldash_user_items_meta`）の中の行でない印 `merged`（`{ at }`）に書く（新しい保存の鍵は作らない）。
- 雲の墓標が、その鍵の送る待ちの英語の語より新しく、その語をほかの端末が見られなかったときだけ、生きた行の違うカード（§18.2）と同じに語を新しい鍵へ移して残す。見られなかった語: この端末がまだ一度も雲と合わせていない（印 `merged` が無い。ゲストの「はい」・表の前から使っている端末）か、語を足した時刻が最後に合わせた時刻より後。移した語は送り、ほかの端末にも届く。墓標はその鍵に残る。ただし墓標のカードは分からないので、一度も合わせていない端末に同じ語（同じ単語帳を先に足した語など）があると、ほかの端末で消した語でも別の鍵で戻る（ゲストの「はい」の道。§18.6 の (7)）。
- 一度でも雲と合わせた端末では、最後に合わせたときに端末にあった語（ほかの端末が取り込めた語）と、足した時刻の無い語は、今どおり新しい墓標が勝つ（送った後にほかの端末で消された語を戻さない。T21c）。一度も合わせていない端末では、足した時刻の無い語も移して残す（足した時刻を見ない。この形を留める検査は無い）。端末の語が墓標より新しい（または同時刻）ときも今どおり端末の語が勝つ（T15f）。
- 残ること（§18.6）: 合わせた後に足して送った語を、ほかの端末が取り込んで消し、この端末がその前に答え（訳の直し・移動・単語帳の名前の変更も）て送れていないと、その語は別の鍵で戻る。この版で最初の取り込みは印 `merged` が無いので、同じ形の語が 1 回だけ戻ることがある。ゲストの「はい」で、ほかの端末で消した語が戻る形もある（上。§18.6 の (7)）。どれも、戻るのは消した語。
- 乱数の 2 台の取り込み（同じ記録を b6ac0f3 と直しの後で再生）: 全部の組 2,500 で 3 状態の消え 77 → 56、語の消え 201 → 156、戻る語 10 → 11（上の残ることの形）。実際に近い組の数は §18.6（読まずに送る送りと、表を後で作る道を入れると、消えが残る）。
