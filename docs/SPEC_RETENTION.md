# 記憶の保持率（7 日・30 日）の仕様 — Phase 1: 実測の記録と表示

> 2026-10-08 起草（Batch 55）。事前調査は scratchpad の REPORT.md（既存の記録には初回学習日時・時刻付きの回答履歴・学習時間が無く、過去分は遡って測れない、という結論）。
> Phase 1 は **この端末の記録だけ**で、**実測だけ**を出す。予測モデル（Phase 3）と 2 台目への同期（Phase 2、SQL が要る）は別フェーズ。
> 実装: `js/retentionLog.js`（語ごとの記録）・`js/studyTime.js`（日別の学習秒数）・`js/retentionCalc.js`（集計の純関数）・`js/retention.js`（学習データの 1 枚）。単体テスト `node scripts/test-retention.mjs`、E2E「retention:」。

## 1. 定義

| 用語 | 定義 |
|---|---|
| 覚えた日（t0） | その語を**初めて自力で思い出せた**時刻（`recordRecallSuccess` の初回）。ただし「知ってた」状態の語（`knownOnSight && recallFail === 0`、js/categoryProgress.js と同じ条件）は除く。**測定の開始前（または別の端末）にすでに自力正解のある語**（この正解の前に `lastRecallSuccessAt` があった語）にも立てない（過去分は遡って測れないので分母に入れない。§4-3）。例外は知ってた語が後でつまずき、そのあと**初めて**思い出せたとき: その時刻が t0（`history` の最後の × のあとに ○ が無いとき。× が流れている・`history` が無いときは学び直し済みとみなして立てない）。ISO で保存し、判定はすべて**ローカル日の差（整数日）** |
| 7 日後の窓 | t0 の日から **+6〜+8 日**。30 日後の窓は **+27〜+33 日** |
| 窓の回答 | 窓に入って**最初の** o/x（思い出せた／思い出せなかった）。1 回だけ書く（write-once）。同じ日の再出題・翌日の○で上書きしない（最初に問われたときの状態を採る） |
| 復習 | t0 の**翌日以降**に o/x の回答があった**日の数**。同じ日の反復（学習ループの○4 回・失敗後の再出題）は数えない。窓の回答に、その**前**の復習日数 `rv` を添える |
| 復習なし／あり | `rv === 0`／`rv >= 1`。表示は必ずこの 2 行。混ぜた 1 本の率は出さない |
| 語の状態（窓ごと） | 到達前（経過日数が下限より前）＝何にも数えない／測定中（窓の中で未回答）＝未測定に数えない／未測定（窓を過ぎて未回答）／測定した（窓の回答あり） |
| 保持率 | 復習なし: `w.r==="o" && rv===0` の語数 ÷ `w あり && rv===0` の語数。復習あり: `rv>=1` で同様。7 日・30 日で別々 |
| 定着 | 7 日後の窓で思い出せた語（`w7.r === "o"`。復習の有無を問わない） |
| 学習時間 | 記録イベント（出題 `recordPlay`・完答 `recordCorrect`・思い出せず `recordRecallFail`・自力正解 `recordRecallSuccess`）ごとに、前のイベントからの経過秒をその日に足す。1 回の経過は **60 秒**まで（離席・無操作を打ち切る）。ページを開いて最初のイベントは足さない。Phase 1 は全モード合算 |
| 1 時間で定着 | 定着した語数 ÷ （**今日 − 7 日 まで**の日の学習秒数 ÷ 3600）。直近 7 日の語はまだ測れないので、その時間も分母に入れない。学習時間が 0 なら「–」 |

o/x は既存の `recordRecallSuccess / recordRecallFail` をそのまま使う（`history` と同じ基準）。Study／Challenge／Daily ではヒント 1 文字目・Enter の答え表示・1 打ミスがすべて ×、Battle はパスだけ ×。保持率には綴りの打鍵の精度が含まれる（過小評価の方向）。別解受理は記録自体が無いので測定に入らない。

## 2. 保存（新しい localStorage キーだけ。word_stats には書かない）

```
spelldash_retention = {
  [wordId]: {
    f:   "2026-10-08T01:23:45.000Z",  // t0（ISO）
    d:   "2026-10-15",                // 最後に復習として数えた回答日
    n:   3,                           // 復習した日数
    w7?:  { t: "2026-10-15", r: "o", rv: 2 },  // 7 日窓の最初の回答。rv = その前の復習日数
    w30?: { t: "2026-11-06", r: "x", rv: 5 }
  }
}
spelldash_study_time = { "2026-10-08": 412.5, ... }   // 日別の秒数。120 日で切る
```

- `CURRENT_SCHEMA_VERSION` は 6 のまま。移行なし。キーが無い／壊れていても読む側は空扱い。
- 語あたり約 100〜180 B で回答数に依らない。2,000 語で 360 KB 以下。
- `spelldash_` 前置なので、バックアップ／復元・別アカウントでの消去（js/backup.js）は自動で対象。
- 書き込みはすべて try/catch。失敗してもゲームには影響しない（js/activity.js と同じ作法）。
- 呼び出しは `js/stats.js` の 4 関数の**末尾**（`saveWordStats / markWordDirty` の後）。`recordRecallSuccess` は `noteFirstRecall` → `noteAnswer("o")`、`recordRecallFail` は `noteAnswer("x")`、4 関数とも `touchStudyTime()`。`recordCorrect` が先に走るので `knownOnSight` は確定している。`recordRecallSuccess` だけは先頭で上書き前の `lastRecallSuccessAt` を `const` に読んで `noteFirstRecall` に渡す（読むだけ。Recall Loop の値・順序は変えない。末尾では上書き済みで「以前に覚えていた語か」が分からないため）。

## 3. 表示（学習データ「今週」タブ、推移の直後。全部無料）

- 見出し「記憶の保持率」。説明 1 文: 「覚えた日から 7 日後・30 日後に、最初に答えたとき思い出せた割合。実測。」
- 行（`.weekly__grid`。**0 の行は出さない**）: 「7 日後（復習なし）」「7 日後（復習あり）」「30 日後（復習なし）」「30 日後（復習あり）」（`72<small>%</small>`）、「測定した語」「未測定」（`N<small> 語</small>`。30 日のぶんは「（30 日 M 語）」）、「1 時間で定着」（`N<small> 語</small>`、小数 1 桁。学習時間 0 なら「–」）
- 注記: 「7 日後＝覚えた日の 6〜8 日後、30 日後＝27〜33 日後の最初の回答。復習＝その前に別の日に答えた日数。窓に出題されなかった語は未測定。週間レポートの思い出せた率（今週の復習の成功率）とは別。復習の予定は翌日から入るので、続けた人の語は復習ありに寄る。」
- 行が 1 つも無いとき: 「覚えた語が 7 日たつと、保持率がここに出る。測定は YYYY/M/D 以降に覚えた語。」（YYYY/M/D = いちばん早い t0、無ければ今日）
- 「予測」という数字はどこにも出さない。`nextReviewAt`（次の復習の予定）・記憶ゲージは予定であり保持率ではないので同じ枠に並べない。

## 4. 既知のバイアス（解釈のときに読む）

1. **復習なしは「初日以降に来なかった人の語」に偏る**: SRS は初回○の翌日に必ず復習を予定する（js/stats.js）。順守した人の語は 7 日目に必ず復習ありになる。復習なし／ありの差は「復習の効果」ではなく「続けた人と途切れた人の差」を含む。
2. **30 日は生存バイアス**: 習得（mastered）した語は出題されない（due 対象外）ので、30 日時点で習得済みの語は未測定に落ちる。30 日後の母数は「まだ習得していない語」に寄る。Phase 2 で未測定の内訳に「習得済み」を出す余地。
3. **過去分は測れない**: 配信前に覚えた語は t0 が無く、分母に入らない。7 日後の数字は配信 6〜8 日後から、30 日後は 27〜33 日後から出る。遡りの近似（`dailyLearningDate` など）は入れない（実測の名に反する）。
4. **打鍵の精度を含む**: 1 打ミスで × になるので、綴りを思い出していても指が滑れば ×。保持率は記憶だけの率より低く出る。
5. **学習時間は近似**: イベント間の経過の合計で、1 回 60 秒で打ち切る。考えている時間は入るが、長い離席は 60 秒として入る。Battle の試合時間も含む（全モード合算）。
6. **この端末だけ**: 2 台で使う人の記録は端末ごとに分かれる（Phase 2 で同期）。
