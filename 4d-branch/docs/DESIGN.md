# 4D Branch 設計書（MVP）

目標・行動・出来事・結果をノードとして記録し、相互につないで「未来の分岐」を見える化するメモ帳。
一般的なフローチャートと違い、**異なるプロジェクトの分岐が交差・合流し、相互に影響する**ことを描けるのが核。

> 依頼文の「添付画像」は開発環境に届いていなかったため、画面構成の文章指定（左＝プロジェクト／シナリオ、中央＝無限キャンバス、
> 右＝詳細、上＝表示切替・検索・編集ツール、下＝時間軸とシナリオ切替、ダークモード基調）をもとに設計した。
> 画像を共有してもらえれば、色・余白・ノードの形をそれに寄せて調整する（色はすべて `src/styles/tokens.css` と
> `src/model/constants.ts` の 2 か所に集めてあるので、差し替えは小さく済む）。

## 2. 技術構成

| 項目 | 採用 | 理由 |
| --- | --- | --- |
| 置き場所 | このリポジトリの `4d-branch/`（独立） | SpellDash のコード・設定・データを一切共有しない。独自の `package.json`・ビルド・テスト・デプロイ設定を持つ。SpellDash の配信からは `.vercelignore` で除外。将来 `git subtree split --prefix=4d-branch` で別リポジトリへそのまま切り出せる |
| 言語 | TypeScript（strict） | データモデル（グラフ・スキーマ・移行・取り込みの検証）が製品の中心なので、型で壊れにくくする |
| ビルド | Vite | 開発サーバーと静的ファイルへのビルドだけ。出力は `dist/` の静的ファイルで、サーバー不要 |
| 実行時の依存 | **なし**（UI フレームワーク不使用） | 2,000 ノード超の描画を自前で最適化するため／依存の更新に振り回されず長く動かすため／オフラインで確実に動かすため |
| グラフの描画 | Canvas 2D | DOM を 2,000 個並べるより速い。画面内だけ描く（カリング）・縮小時は省略描画（LOD） |
| UI 部品 | DOM + CSS（変数でテーマ管理） | サイドバー・詳細・ダイアログは文字入力や読み上げに強い DOM で |
| 状態管理 | 自前のストア（正規化・不変更新・トランザクション） | すべての変更が 1 か所を通るので、Undo/Redo・自動保存・再描画が漏れなくつながる |
| 保存 | IndexedDB（本体・バックアップ）＋ localStorage（緊急コピー・表示設定） | 容量が大きく非同期な IndexedDB を主に、閉じる瞬間の書き込みは同期の localStorage で守る |
| テスト | Vitest（単体）／ Playwright（ブラウザでの通し・性能計測） | |
| デプロイ | Vercel の別プロジェクト（Root Directory = `4d-branch`）など任意の静的ホスティング | |

### 実行時の構成

```
main.ts ── Persistence（IndexedDB・ロック・バックアップ）
   │            ▲ 変更イベントで自動保存
   ▼            │
 Store（ドキュメント・トランザクション・履歴） ──変更イベント──▶ 派生データ（隣接・所属・表示状態）
   ▲                                                            │
   │ commands（作成・接続・分岐・合流・削除…）                       ▼
 UI（上部・左右・下部・ダイアログ）  ◀── UiState（選択・絞り込み・時点・表示切替） ──▶ CanvasView（描画・操作）
```

- UI もキャンバスもキーボードも、データを変えるときは必ず `commands` → `store.transact()` を通す。
- 選択・絞り込み・表示のような「見え方」は `UiState` に置き、ドキュメントにも履歴にも入れない（Undo で選択が戻ったりしない）。

## 3. データモデル

### 3.1 方針

- **全プロジェクトで 1 つのグラフ**。プロジェクトはノードを入れる「箱」ではなく、ノードに付く**所属（多対多）**。
  同じノードを複数のプロジェクトから参照できる（例: 「広告運用を学ぶ」は 3 プロジェクトすべてに所属）。
- **接続（エッジ）はノードと独立したデータ**。種類（関係）・条件・ラベル・シナリオを持つ。
- **循環・条件分岐・合流**をデータの形で禁止しない（任意の有向グラフ）。禁止するのは自己ループと、同じ向きの重複だけ。
- **時間とシナリオは拡張できる形**（`time` オブジェクト、`scenarioIds` と独立した `Scenario`）。
- すべてのエンティティに `meta`（自由な拡張欄）。**知らない項目は読み込み・保存で消さない**（新しい版で作ったファイルを古い版で開いても欠けない）。

### 3.2 ドキュメント

```jsonc
{
  "schema": "4d-branch",          // ファイルの種類
  "version": 1,                   // スキーマの版（移行に使う）
  "id": "d_x1y2z3...",
  "title": "マイ・ブランチ",
  "createdAt": "2026-11-08T12:00:00.000Z",
  "updatedAt": "2026-11-08T12:34:56.000Z",
  "projects":  { "p_...": Project },
  "scenarios": { "s_...": Scenario },
  "nodes":     { "n_...": Node },
  "edges":     { "e_...": Edge },
  "projectOrder":  ["p_...", ...],  // 左サイドバーの並び
  "scenarioOrder": ["s_...", ...],
  "meta": {}
}
```

### 3.3 ノード

```jsonc
{
  "id": "n_k3j9...",
  "type": "action",               // goal 目標 / action 行動 / branch 分岐 / result 結果
  "title": "広告運用を学ぶ",
  "body": "Google・Meta 広告の基礎から…",  // 文章（複数行）
  "status": "active",             // open 未着手 / active 進行中 / done 達成 / dropped 見送り
  "time": {                       // 時間情報（拡張可能: 期間・不確かさの幅などを足せる）
    "due": "2027-03-31",          // 期限（日付のみ・ローカル日付）
    "start": null                 // 開始（任意）
  },
  "conditions": [                 // 条件（チェックリスト）
    { "id": "c_...", "text": "月 10 時間を確保できる", "met": true }
  ],
  "tags": ["スキル", "集客"],
  "projectIds": ["p_spell", "p_fc", "p_ind"],  // 複数プロジェクトから参照（空なら未分類）
  "scenarioIds": [],              // 空 = 全シナリオ共通 / 指定 = そのシナリオだけの要素
  "x": 120, "y": -40,             // 共通キャンバス上の中心座標
  "collapsed": false,             // このノードの先（下流）を折りたたむ
  "createdAt": "...", "updatedAt": "...",
  "meta": {}                      // 拡張欄（将来の AI 分析結果・スコアなど）
}
```

### 3.4 接続（エッジ）

```jsonc
{
  "id": "e_...",
  "source": "n_...",              // 向き: source → target
  "target": "n_...",
  "relation": "supports",         // leads 進む / condition 条件付き / supports 相乗効果 / blocks 阻害 / feedback 循環
  "label": "実績が営業材料になる",
  "condition": "",                // 条件分岐の条件（例: 副業の月収 30 万円が 3 か月続いたら）
  "scenarioIds": ["s_early"],     // 空 = 全シナリオ共通
  "collapsed": false,             // この線の先を折りたたむ
  "createdAt": "...", "updatedAt": "...",
  "meta": {}
}
```

### 3.5 プロジェクト・シナリオ

```jsonc
// Project
{ "id": "p_...", "name": "SpellDash事業", "color": "#FF7A59", "description": "", "createdAt": "...", "updatedAt": "...", "meta": {} }
// Scenario
{ "id": "s_...", "name": "早期独立", "color": "#F2C14E", "description": "", "createdAt": "...", "updatedAt": "...", "meta": {} }
```

### 3.6 決まり（不変条件）

| 決まり | 守る場所 |
| --- | --- |
| エッジの両端のノードは必ず存在する（ノード削除で接続も消える） | ストア・取り込み |
| 自己ループ（A→A）は作らない。同じ向きの重複（A→B が 2 本）も作らない。逆向き（B→A）は可＝循環 | 接続の操作・取り込み |
| `projectIds`・`scenarioIds` は存在するものだけ（削除時に各ノード・エッジから外す） | ストア・取り込み |
| 日付は `YYYY-MM-DD`、時刻は ISO 8601 | 取り込み時に正規化 |
| 知らない項目は捨てない（そのまま保持して書き出す） | 取り込み・保存 |

### 3.7 派生データ（保存しない・変更のたびに作り直す）

- 隣接（ノード → 入る線・出る線）、プロジェクト → ノード、タグ → 件数
- **共有ノード**: 2 つ以上のプロジェクトに所属するノード（カードに所属の色の点が並ぶ）
- **交差リンク**: 両端のノードに共通のプロジェクトが 1 つも無い接続（プロジェクト間の影響として太く光らせる）
- 表示状態（各ノードの「隠す／薄くする」）: プロジェクトの絞り込み・シナリオ・時点・検索・折りたたみ・経路強調から計算

### 3.8 折りたたみ（循環・合流があっても破綻しない計算）

1. 折りたたんだノードの出る線と、折りたたんだ線を「止める線」にする。
2. **入口**から、止める線を通らずにたどれるノードを表示する。入口は
   - 入る線の無いノード。ただし「フィードバック」の線は数えない（循環を閉じる線なので、戻ってこられる根は根のまま）
   - フィードバック以外の線で外から入られない循環のかたまり（強連結成分）では、その中の折りたたみの起点（無ければ全員）
     → 循環だけのかたまりでも、折りたたんだノード自身は消えない
3. **合流**: 別の親が見えていれば消えない（入口からたどれるため）。
4. 折りたたんだノードには「+N」を出す。N はその先で、隠れているノードだけをたどって届く数（見えている所で止める＝開くと出てくる物）。
5. 検索で隠れたノードを選ぶと、上流の折りたたみを開いて表示する（元に戻せる）。プロジェクトの絞り込み・シナリオの「隠す」で隠れていれば「薄くする」表示に切り替える。

シナリオの推定（選ばれなかった分岐の先を薄くする）も同じ入口の決まりで、「シナリオに入らない線」を止める線として計算する。

### 3.9 シナリオと時間

- シナリオを選ぶと、`scenarioIds` が空（共通）かそのシナリオを含む要素だけが明るく、ほかは薄く（設定で「隠す」も可）。
  分岐ノードから出る線にシナリオを付けると「このシナリオではこちらへ進む」を表せる。
- 下部の時間軸で時点を選ぶと、期限がその時点より後のノードが薄くなる（未来が時間とともに現れる）。期限の無いノードは常に表示。
- 拡張: シナリオごとの上書き（期限・状態の差分）や確率は `Scenario.meta`／`Node.meta` に足せる。`time` は期間や不確かさの幅を足せる形。

### 3.10 版と移行

- `version` が古いファイルは `migrate()` で順に上げる。新しすぎる版（未知のメジャー）は読み込まずに理由を表示。
- 取り込みは「検証 → 正規化 → 件数と警告の確認 → 置き換え or 追加」。壊れた要素は捨てて警告に出す（全体は捨てない）。
- 外で作った JSON（外部の AI・表計算・手書き）もなるべく受ける: 配列の形、数の ID（`1, 2, 3`）、接続の `from` / `to`、
  時刻つきの日付（`2027-03-31 10:00`）。空白入りなど使えない ID は振り直し、接続・所属の参照もそちらへ読み替える。
  `constructor`・`toString`・`__proto__` など JavaScript の組み込みの名前は ID に使わない（辞書は自分の項目だけを引く）。
  日付は入力欄と同じ 1900〜2999 年。読めない期限は外して警告に出す。

### 4.1 領域

| 領域 | 中身 |

| 右 | 選択中のノードの詳細（種類・状態・タイトル・文章・期限・条件・タグ・プロジェクト・シナリオ・接続一覧）、接続線の詳細（関係・ラベル・条件・シナリオ・折りたたみ・向きの反転）、複数選択のまとめ操作（合流・整列・一括でプロジェクト／タグ） |
| 下部 | 時間軸（期限のあるノードの印・今日・時点のつまみ・再生）とシナリオ切替 |

### 4.2 ノードの見分け（色＋アイコン＋形）

| 種類 | 色 | アイコン | 形 |
| --- | --- | --- | --- |
| 目標 goal | 琥珀 `#FFB547` | 的（◎） | 角丸＋内側の二重線 |
| 行動 action | 青 `#4DA3FF` | 稲妻 | 角丸 |
| 分岐 branch | 紫 `#B983FF` | 枝分かれ | 左右がとがった六角形 |
| 結果 result | 緑 `#3DD9A4` | 旗 | 丸みの強い角丸 |

カードは 212×96（ワールド座標）。下段に所属プロジェクトの色の点（共有ノードは点が複数並ぶ）・期限・条件の達成数・タグを出す。
縮小したときは、カードの下の縁に所属プロジェクトの色の帯を出す（どのプロジェクトのノードか・共有かが遠目でもわかる）。

### 4.3 接続線（方向と関係）

すべて矢印で向きを示す。関係ごとに線の形と色を変え、ラベル・条件は線の中ほどに小さく出す。

| 関係 | 線 | 色 | 用途 |
| --- | --- | --- | --- |
| 進む leads | 実線 | 灰青 | 次の段階・因果 |
| 条件付き condition | 破線 | 黄 | 分岐の先（条件の文を持つ） |
| 相乗効果 supports | 点線＋光 | 桃 | 他プロジェクトへの後押し |
| 阻害 blocks | 実線＋止め線 | 赤 | リスク・トレードオフ |
| 循環 feedback | 長い破線 | 水色 | 結果が行動に戻るループ |

交差リンク（プロジェクトをまたぐ線）は太く、外側に光をつけて目立たせる。

### 4.4 操作

| 操作 | マウス／トラックパッド | キー |
| --- | --- | --- |
| 移動（パン） | 空き所をドラッグ／2 本指スクロール／スペース＋ドラッグ | 矢印（選択なし） |
| 拡大縮小 | ピンチ／⌘（Ctrl）＋スクロール（設定でホイール＝ズームに切替可） | `+` `-` `0`（100%）`F`（全体・選択に合わせる） |
| 選択 | クリック、⇧／⌘クリックで追加、⇧＋ドラッグで範囲選択 | ⌘A |
| ノードを作る | 空き所をダブルクリック、上部の ＋目標 など | `N` |
| 分岐（子）を作る | ノード右の ● をドラッグして空き所で離す | `Tab` |
| 接続 | ● を別のノードへドラッグ（複数選択中は全部から接続） | |
| 合流 | 複数選択 → 詳細の「合流ノードを作る」 | |
| タイトル編集 | ノードをダブルクリック | `Enter` / `F2` |
| 種類の変更 | 右クリックメニュー・詳細 | `1`〜`4` |
| 折りたたみ | ノード右下の「+N」・右クリック・詳細 | `C` |
| 削除 | 右クリック・詳細 | `Delete` / `Backspace`（直後のお知らせから元に戻せる） |
| 元に戻す／やり直し | 上部のボタン | ⌘Z ／ ⇧⌘Z（Ctrl+Y） |
| 検索 | 上部の検索欄（`#タグ` でタグ検索） | ⌘K ／ `/` |
| 保存 | 自動 | ⌘S（すぐ保存） |

### 4.5 初回起動

1. 保存データが無ければデモ（3 プロジェクト）を読み込み、ようこそ画面を出す。
2. 「操作ガイド」を選ぶと、7 つの手順で各領域を順に照らして説明する（いつでもスキップ可、`?` から再表示）。
3. ヘルプにショートカット一覧。

## 5. 保存とデータ保護

| 守り | 中身 |
| --- | --- |
| 自動保存 | 変更のたびに IndexedDB へ（0.3 秒まとめて書く・最大 2 秒待ち）。上部と左下に「保存中／保存済み」 |
| 離脱時 | タブが隠れたら即保存。閉じる瞬間に未保存があれば localStorage に**緊急コピー**を同期で書き、次回起動時に新しい方を採用（競合したら両方残す） |
| 書き込みの競合 | 保存ごとに版番号（rev）を確かめ、知らない書き込みがあれば上書きせず、手元の内容をバックアップへ退避して知らせる。「保存されている最新を開く」ときも、その時点のこのタブの内容をもう一度退避してから開く |
| 新しい方の見分け | ドキュメントの `updatedAt` は変更のたびに必ず進める（同じミリ秒・時計の戻り・古い時刻のファイルやバックアップとの入れ替えでも）。緊急コピーは「本体がその元の版のまま」なら写しを採る |
| 複数タブ | Web Locks で編集できるタブを 1 つに。他のタブは閲覧のみ（「このタブで編集する」で引き継ぎ） |
| バックアップ | 自動（変更がある間 10 分ごと・最新 24 件）、日次（その日最初の起動時・30 日分）、手動（名前つき）、安全用（取り込み・復元・初期化の直前） |
| 復元 | バックアップ一覧から復元（復元の直前に今の状態も安全用に残す）・その場で JSON をダウンロード |
| 消えにくくする | `navigator.storage.persist()` を要求（ブラウザの自動削除から保護） |
| 書き出し | いつでも JSON でエクスポート（そのまま取り込める）。取り込みは置き換え（直前に自動バックアップ・Undo 可）か追加 |
| 操作の取り消し | 削除・取り込みも含めて Undo 可。削除直後のお知らせに「元に戻す」 |
| 試すだけの表示 | `?stress=2000` などの検証用データは**保存しない**一時表示（本来のデータに触れない） |

### 5.1 アカウントへの同期（claude.ai の Artifact 版）

Artifact として公開した版では、手元（IndexedDB）を主にしたまま、claude.ai の `db` 機能で**あなただけが読める場所**にも写しを置く。
別の端末・別のブラウザで開いても同じ内容が出て、ブラウザのデータを消しても失わない。Artifact の外（Vercel など）では動かない（`window.claude` が無い）。

| 項目 | 中身 |
| --- | --- |
| 置き場所 | `data/users/<id>/fourd`（マニフェスト）・`fourd/parts/<世代>-<番号>`（中身の分割）・`fourd-lock`（書く間の貸し出し）。`data/users/<id>/` は本人以外（持ち主も）読めない |
| 形 | JSON → gzip（使えないブラウザは UTF-8 のまま）→ base64 を 180,000 文字ずつに分割（1 文字 1 バイトなので 1 文書 256 KiB の内側）。**最後にマニフェストを書く＝確定**。読むときは SHA-256 で確かめる |
| 古い世代 | 直前の世代と 2 分以内の世代は、読んでいる途中の端末のために残す。それより古い世代・覚えておく数（20）を超えた世代は確定の後に消す。失敗した送信の分割はその場で消し、どこからも指されない分割は（10 分より古ければ）掃除する。容量がいっぱいのときも掃除してから待つ |
| 送る時機 | 編集から 5 秒まとめて（打ち続けても、最初の変更から 20 秒で送る）。送る内容を固めたら窓を区切る（送信が続けざまにならない）。タブが隠れたとき・⌘S ですぐ。送るのは編集できるタブだけ |
| 初めての同期 | この端末にまだ基準が無いとき: 手元が捨ててよい中身（何もしていないデモ・空。動かした・畳んだだけも含む）ならアカウントの内容を採る。アカウント側がそうなら手元を送る。**両方に中身があれば「どちらの内容を使いますか？」と聞き、決めるまで送らない**（使わなかった方はバックアップへ）。前に別のアカウントで同期していたブラウザの内容は、聞かずに今のアカウントへ送らない。初めての読み込み・選んだ切り替えは「元に戻す」の対象にしない |
| 別の端末の変更 | 手元に未送信の変更が無ければ取り込む（読み終えてから・入れ替える直前にもう一度確かめる。題名をその場で入力している間は待つ。取り込む前の手元は安全用バックアップへ・元に戻すでも戻せる）。両方変わっていたら、相手の内容を「退避」バックアップに残してから手元を送る（同じ相手の世代は 1 回だけ）。退避できないブラウザでは上書きせずに止める。中身が同じなら何もしない |
| 同時に書かない | 書く直前に短い貸し出し（6 秒・返却なしで切れる）を取り、マニフェストを読み直す。分割を書いたら、確定の直前に貸し出しを延ばしてもう一度読み直し、変わっていたら確定せずに決め直す |
| 見張り | マニフェストを見張る。切れたら間をあけて何度でも張り直す。画面に戻ったとき・つながったときにも確かめる。自分の確定の知らせは無視する |
| 失敗したとき | 混み合い 30 秒・つながらない 15 秒・容量 10 分は送らない（入力があっても縮めない）。新しい版のアプリで保存された写し・読めない写しは上書きせずに止める。止めた同期は「バックアップと復元」の「同期をやり直す」で再開 |
| 壊れた写し | その世代だけ、手元の内容で書き直す（手元は無事。別の端末が直していれば読む） |
| 書けないとき | サインインしていない・閲覧のみの共有では、このブラウザだけに保存（画面に出す） |
| 公開の設定 | `db` の決まり: 全体は編集者だけが読み書き、`data/users/{self}` は本人（Contributor 以上）が読み書き。ほかに `user`（本人の ID）と `downloads`（書き出し） |

Artifact の中ではページから直接ファイルを保存できないため、JSON の書き出しは `downloads` 機能で保存を頼む（使えない画面では、内容をコピーできるダイアログを出す）。
クエリ文字列が渡らないので、性能確認は `#stress-2000`（同じ画面で一時表示に切り替わり、上の帯の「ふだんの画面へ」で戻る。Artifact の中では新しいタブを開けない）。
手元（IndexedDB）はブラウザのプロフィールごとなので、同じブラウザで別のアカウントに切り替えたときは「初めての同期」の決まり（聞いてから）に従う。

## 6. 性能設計（2,000 ノード超）

- **描画**: Canvas 2D。画面内の要素だけ描く。必要なときだけ描き直す（変更・移動の間だけ requestAnimationFrame）。
- **意味のあるズーム（LOD）**:
  | 拡大率 | 描き方 |
  | --- | --- |
  | 80% 以上 | すべて（種類・状態・期限・タイトル 2 行・所属の点・条件・タグ・線のラベル） |
  | 30〜80% | 細部を省き、タイトルの文字を大きくして画面で約 11.5px に保つ（全体を見ながら読める）＋所属の帯 |
  | 10〜30% | 色の箱と所属の帯。目標・選択中・検索の当たりの名前を、重ならないように画面に目印として出す |
  | 10% 未満 | 点。線は薄く（毛玉にしない） |
- **ドラッグ**: 動かしている間はストアを触らず、離した時に 1 回のトランザクションで確定（Undo 1 回で戻る）。
- **派生データ**: 変更のたびに O(ノード＋接続) で作り直す（5,000 要素でも 1 ms 程度）。文字の折り返しはノードごとにキャッシュ。
- **UI**: リスト表示は見えている行だけ作る（仮想スクロール）。検索候補は上位 50 件。
- **保存**: まとめて書く（デバウンス）。2,000 ノードでも 1 回数 ms。
- **計測**: `?stress=2000`（一時表示）で 2,000 ノード・約 3,000 本を生成し、E2E でパン・ズーム中の 1 フレームの描画時間を測る。
  手元（ヘッドレス Chromium）の結果: 全体表示・中間・寄り・選択中（経路の強調と流れの動きあり）のどれも平均 1〜3 ms・95% 点 7 ms 以下
  （E2E は 95% 点が 33 ms を超えたら落ちる）。

## 8. テスト方針

- **単体（Vitest）**: 正規化と移行（壊れたデータ・知らない項目の保持）、ストアと Undo/Redo（まとめ・置き換えの取り消し）、
  折りたたみ（循環・合流）、経路強調、検索の正規化（全角半角・カタカナ／ひらがな）、取り込みの追加（ID の振り直し・名前での統合）、
  保存（rev の競合・緊急コピーの採否・バックアップの間引き）。
- **E2E（Playwright・本番と同じ CSP の下で）**: ようこそ → 操作ガイド → ダブルクリックで作成 → Tab で分岐 → ● のドラッグで接続 →
  何もない所で離して分岐 → Undo/Redo → 削除とお知らせからの復帰 → 詳細の編集 → 検索 → 折りたたみ → 時間軸とシナリオ →
  再読み込みで残る → 2 つ目のタブは閲覧のみ・引き継ぎ → エクスポート → 取り込み（追加）と Undo → バックアップ →
  閉じる直前の変更が残る（緊急コピー）→ 2,000 ノードの描画時間・一時表示が保存されない → ページのエラーが無い。
