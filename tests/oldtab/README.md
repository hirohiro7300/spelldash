# 旧タブの証明（tests/oldtab）

直前の本番のコードを開いたままのタブ（旧いタブ）から、アカウント A の記録がアカウント B へ 1 件も送られないことを確かめる。
新しいコードで旧いタブをまねた模型は使わない。旧いタブで動くのは、本番に配った木そのもの（git archive）。

## 何を使うか
- 旧い木: `--old` に渡した git の ref を git archive で取り出した物。アカウントの分離の前の最後の本番 `0507672`（CI もこれに固定）。
  - 分離の入った木（`js/areaGuard.js` がある）は旧い側に渡せない（止まって終わりの値 2）。分離の入った旧いタブは切り替えの画面（/switch.html）を通って新しい文書になり、B として動いてよいので、この 5 段の決まり（旧いコードのタブが B として動いたら漏れ・旧いタブは最後まで旧いコード）が合わない。分離の後の本番を旧い側にするなら、「旧いタブが切り替えの後に B として動いてもよいが A の行を送らない」を見る別の 5 段を作る。
- 新しい木: `--new` の置き場か git の ref（既定はこの木）。ほかの worktree も渡せる。
- サーバー: 1 つのオリジン。配信を替える前は旧い木、替えた後は新しい木を返す。開いているタブは読み込んだコードを持ち続け、その後の取得は新しいファイルを受ける（本番の配信の入れ替えと同じ）。応答の headers（CSP を含む）と redirects は、その時に配っている木の `vercel.json` に従う。静的ファイルは `cache-control: public, max-age=0, must-revalidate` と ETag。Service Worker は各木の `sw.js` がそのまま動く。
- 認証の部品: 本物の部品（包みの名前は `lib/authLib.mjs` の `PACKAGE`）の 2.118.0。リポジトリには入れず、検査の時に `lib/authLib.mjs` が登録所から取って作る（下の「認証の部品の取り方」）。両方の木の `js/supabase.js` にある差し替え口 `window.__SUPABASE_MODULE_URL` で読ませる。E2E のスタブは使わない。
- にせの受け口（`lib/fakeSupabase.mjs`）: 認証（health・otp・verify・token の更新・user・logout）と表（select・insert・upsert・update・delete と、自分の行だけの権限）を本番の受け口と同じ形で返す。アクセストークンは署名付きトークン（JWT）の形で寿命 100 秒（部品は残り 90 秒を切ると更新するので、更新が何度も起きる）。全部の要求を、どのタブか・Authorization の人・中身・行の user_id ごとに記録する（通信の切れたタブの届かなかった要求も、誰として送ろうとしたかを残す）。本物のプロジェクトには出ない（名前の引きを 127.0.0.1 以外すべて失敗にしている）。

## 流れ（創業者の 5 段。`lib/scenario.mjs`）
1. 旧い木を配る。A の記録（A だけの語・XP・最高点・Battle・連続日数・マイ単語帳・メモ・日ごとの記録・送信待ちの Battle・表示名）を置いた端末で、旧いタブを 5 つ開いて A でログインし同期させる（`lib/seed.mjs` の `OLD_TABS`）。
   - `old-live`: ホームで学習中（ログインのリンクを開いたタブ。URL は `/#`）→ 裏へ。
   - `old-frozen`: ホームで学習中 → 裏へ → 凍らせる。まずブラウザの開発用の口の凍結（Page.setWebLifecycleState frozen）。画面の無いブラウザの見えるタブでは効かない（試した）ので、検査の時計（そのタブの setInterval が localStorage の `oldtab-harness-tick` に「文書の印:時刻」を書く）が止まらなければスクリプトを止める（Debugger.pause）。
   - `old-offline`: 学習状況のページ → 裏へ → 通信を切る（開発用の口の通信断は navigator.onLine と offline の知らせにだけ効くので、受け口の側でもそのタブの要求を net::ERR_INTERNET_DISCONNECTED で断つ）。
   - `old-visible`: ホームを開いたまま、見えたまま。配信の前にこのタブでトークンの更新を始め、受け口がその答えを、新しいタブの移行が終わるまで止める（docs/SPEC_ACCOUNT_AREAS.md §6 の 2「自分のトークンの更新で旧い鍵を書き戻しても A のまま」の道）。
   - `old-sw`: ホーム（URL に印も `#` も無い）→ 裏へ。新しい木の sw.js が開いている窓を読み直すなら、このタブは読み直される（読み直しの道の確かめ。読み直された後は新しいコードとして判定する）。
2. 配信を新しい木に替え、同じオリジンの別のタブ（new）で新しいコードを開く。移行のある木（`js/areaGuard.js` がある）では、移行が終わって旧い認証の鍵が消えるのを待ってから、`old-visible` の止めていた更新を通す。
3. new で B にログインする（`logout`: A をログアウトしてから B の欄でリンクを頼む／`link`: A のまま B のリンクを開く）。
4. 旧いタブを戻す（凍結を解く・通信を戻す・見える状態・focus）。旧い画面で語に答え（`old-live` と `old-frozen` が 2 語ずつ。画面の読みと focus は page.evaluate、打鍵は page.keyboard。新しい sw.js の読み直しを検査が 204 で止めたタブでも動く）、裏へ回して戻し、読み込み済みの旧いモジュールの同期とセッションの読みを呼び、トークンの更新が起きるまで待つ。
   - その後、新しいタブで新しいコードの文書を開き直す（`/` → 裏と表 → `/switch.html`（ある木だけ）→ 裏と表）。移行の後に旧いタブが旧い鍵（`spelldash_*`）へ書いた値は、新しいコードが次の読み込みの片付け（見張りの頭・切り替えの画面）でだけ扱うので、その道を通して要求と表を判定に入れる。
   - 最後に全部のタブを裏へ回し、旧いタブを閉じる（pagehide の書き出しも旧い鍵へ書く）。閉じた後にもう一度、同じく開き直す。
5. `lib/analyze.mjs` で調べる（下）。
6. A へ戻る（orphans のある木だけ。docs/SPEC_ACCOUNT_AREAS.md §0.3 の 1。`--no-return` で外す）: 旧いタブを閉じた後に、new を A に戻す（`logout` の回は B をログアウトしてから A の欄で、`link` の回は B のまま A のリンクで、B にログインしない回は A をログアウトしてから A の欄で）。学習状況の画面（3 つの札）を読み、裏と表で送り切り、A の領域・送る語の印・A のクラウドの行を読む。もう一度 A から離れ（`link` は B へ・ほかはゲストへ）、A へ戻って同じく読む（2 度取り込まないか）。
   - 見張りのタブ（`lib/watch.html`。検査のページでアプリのコードは無い。配信の前に開き、配信の後の読み直しは 204 で止める）が、ほかのタブの localStorage の書き込みの知らせ（storage イベント）を最初から最後まで聞く。人ごとの領域の鍵（`sd2.<領域>.word_stats`・`sd2.<領域>.dirty_words`）は語ごとの回数・最後に答えた時刻・3 状態の欄と送る語の印に要約し、端末の印（`sd2.area`・`sd2.index` など）はそのまま残す。アプリのページには何も足さない。
   - 節目（3 段の後・閉じた後・1 回目に戻った後・離れた後・2 回目に戻った後）に、見張りのタブで端末の印・localStorage の領域の語の記録・IndexedDB の `areas`（使っていない人の控え）を読む。

回の形:
- `--order normal`（既定）: 2 段で新しいタブが `/` を開き（移行）、3 段で B にログインする。
- `--order direct-link`: 新しいコードの最初の読み込みが B のリンクそのもの（旧いタブしか開いていない端末で B のメールのリンクを開く）。移行と B への切り替えが同じ読み込みで起きる。
- `--login none`: B にログインしない。見えたままの旧いタブの止めていた更新を通した（書き戻しの）後に、そのまま旧いタブを戻す。
- `--release login`: 見えたままの旧いタブの止めていた更新を、移行の後（既定 `migrated`）ではなく、B のセッションが動いて落ち着いた後に通す（切り替えの時の片付けがすんだ後に書き戻す形）。
- 後の 3 つは `--old-auth-lib` の古い部品（2.107.0 より前。更新の結果を旧い鍵へ書き戻す）と使う。書き戻された旧い鍵は、新しいコードが次に開いたページ（見張りの頭・/switch.html）でしか片付けないので、その間に旧いタブが A として動く。
- 書き戻しが起きたかは、旧い認証の鍵の書き込みの知らせ（storage イベント）を旧いタブ 2 つ（`old-live`・`old-visible`。書いたタブには知らせが来ないので 2 つ）で聞いて確かめる（節目の読みだけだと、書き戻しの直後に新しいコードが片付けたときに見落とす）。古い部品の回で書き戻しが見えなかったときは「試していない」に出す。`--expect-writeback` を付けた回は、書き戻しが見えなければ INVALID（CI の古い部品の 2 回に付けている）。

### どのタブが旧いコードのままだったか
- init script が新しい文書のたびに文書の印を作り、検査に知らせる（同じ文書の中の移動では作らない）。配信の後に新しい文書が始まったタブは、その時からは新しいコード。
- 凍った・通信の切れた・見えたままのタブ（`KEEP_TABS`）は、読み直しの届かないタブとして扱う。URL に `oldtab-keep=<名前>` を付け、サーバーは配信の後のその文書の要求に 204 を返す（ブラウザは 204 の文書を表示しないので、新しい sw.js が `client.navigate` で読み直そうとしても旧いコードのまま残る）。止めた読み直しは記録に残す。Service Worker の読み直しを安全の根拠にしないため（本番でも凍った・裏の・通信の切れた・Service Worker の無いタブは読み直されない）。
- 回の終わりに、旧いタブごとに「旧いコードのまま／新しいコードになった」と、その理由（Service Worker なしの回・読み直しを止めた・URL の `#` で同じ文書の中の移動になった・読み直しの試みが無かった）を出す。

### 旧いタブの中の書き込みの記録（`lib/storageTap.mjs`）
- 分離の入った木の見張り（`js/areaGuard.js`）は、移行の後に旧いコードのタブが旧い場所（`spelldash_*`）へ書いた人の記録を、storage の知らせで数ミリ秒のうちに IndexedDB の orphans へ写して localStorage から消す。だから「旧い画面で答えた」は、答えた後の localStorage では確かめられない。
- init script が、旧いコードの文書の中で、ページのスクリプトより前に `Storage.prototype.setItem`・`removeItem`・`clear` を包む。旧い場所の鍵への書き込みを、書いたその時に、鍵・大きさ・値の digest（FNV-1a 32 ビット）と、語の記録（`spelldash_word_stats`）なら前の値と比べて変わった語の回数（playCount・correctCount・recallFail・lastPlayed）として、出した口（exposeBinding）で検査へ知らせる。文書の印も付ける。
- 旧いコードの振る舞いは変えない: 元の口をそのままの `this` と引数で呼び、その戻り値を返し、投げた物（容量の超過・引数の足りない呼び方など）はそのまま投げる。記録の側の失敗（知らせの口が無い・口が投げる）は全部飲み込み、処理されない失敗も残さない。口の名前・引数の数も元と同じ。包みあり・なし・知らせの口なし・口が投げる・外した の 5 通りで、返り値・例外・中身・鍵の一覧が同じことを確かめた（引き継ぎ §15）。
- 包むのは配信の前に始まった文書（旧い木）だけ。配信を替える直前に、包みを外す init script（`disarmStorageTap`）を足す（init script の順番は決まっていないので、どちらが先でも、その後の文書（新しいコード）は元の口のまま）。
- 新しい木に orphans がある（`js/areaStore.js` の `DB_NAME` と `orphans`）なら、4 段の後と閉じた後の開き直しの終わりに、新しいコードのタブで orphans を読む（DB が無ければ作らない。値そのものは記録に残さず、鍵ごとの大きさ・digest と語ごとの回数だけ）。
- 語の記録の書き込みは、変わった語ごとに書く前の値（`prev`）も残す。書いた値 − 書く前の値が、その書き込みで増えた分（A へ戻る段で A へ取り込む量に使う）。

## 判定（`lib/analyze.mjs`）
B はこの検査の中で学習しない。どれか 1 つでも当たれば漏れ（LEAK）:
- B の名前の書き込み（Authorization が B か、行の user_id が B）を、B のクラウドの初めの値と列ごとに比べる。違ってよいのは `updated_at` と、user_progress の `level`・`study_familiar_ratio`・`selected_*` だけ。B のクラウドに無い行（品・Battle・活動など）・消した印・B の行を消すのも漏れ。許す新しい行は、B の今日の日の行で、学んだ印もセットも無く、語の数が B の語の数までの物だけ。違った値が A の値（A が 1 段で書いた値・A のクラウド・A の端末の初めの値）と同じなら、そう書き添える。
- A だけの文字（A の user id・メール・マイ単語帳の語・メモ・表示名・Battle の印）・A の語・行の user_id が A。
- 逆向き（B → A）: A の名前の書き込みに B の語・B だけの文字・user_id が B の行。
- 表の最後の中身も同じ規則で見る。B の初めの行が消えていても漏れ。
- A の語: A だけの語（`A_WORDS`）は B の行にあれば漏れ。A が旧い画面で答えた語のうち公開の語（B が学べば B の行もありうる）は、回数が A の値（A が書いた行・答えた後の旧いタブの端末の値）と同じときだけ「A の語」と書く（B のクラウドに無い行なら、上の規則でどのみち漏れ）。

- A へ戻る段（orphans のある木）: 旧いタブが配信の後に語の記録へ書いた語が、B（とゲスト）の領域に一度でも入った（見張りの知らせ・節目の読みの localStorage と IndexedDB の控え。B の種の語は除く。A の予行の写し `pre:u:A` は A の物）。

A の記録の後退（判定 LOSS。漏れとは別）: 配信の後の A の名前の書き込み（受け口が受けた物）と表の最後の A の行が、A の初めの値（A のクラウド・A の端末）と A がそれまでに書いた値より後ろへ戻ったら当たり。
- 数え上げが減る: 語の play_count・correct_count・typing_miss・recall_fail、xp・best_score・battle_wins／losses／draws／best_win_streak、streak.best、今日の活動の数、日ごとの記録の learned・mastered・sets。
- 日が続いているのに streak.current が戻る。Battle をしていない（勝ち負けの数が増えていない）のに battle_rp・battle_current_win_streak が変わる。
- 品・メモ・マイ単語帳に消した印・中身が空、日ごとの記録の active が戻る、表示名が空、A の行を消す、A の初めの行が表から消える。
- 写しの列が既定に戻る: 旧いコードのタブが A の `selected_category`・`selected_mode` を既定（`all`・`study`）に戻す（移行の後の空の端末の写しを送る形。新しいコードが設定を書き直すのは数えない）。語の `last_played` が空か前へ戻る。
- 配信の前の書き込み（その時の本番の振る舞い）と、受け口が断った書き込みは数えない。
- 旧いコードのタブの決まり: 旧いコードのまま（配信の後に新しい文書が始まる前）の旧いタブが、B のトークンで要求した（読みも）・B のトークンを更新した・行の user_id が B の要求を出した（通信断で届かなかった物も）・旧いモジュールの getSession が B を返した・旧い認証の鍵に B のセッションがあった（節目の読みと、書き込みの知らせの両方で見る）。

A へ戻る段の取り込み（orphans のある木で、その段を流した回だけ。判定 NOT_IMPORTED・DOUBLE。漏れ・後退が無く、全部の段を通った回だけに出す）:
- 量: 旧いタブの語の記録の書き込みごとに、語ごとの「書いた値 − 書く前の値」（遊んだ・正解・思い出せずの 3 つ）を足す。数えた答えの窓の書き込みの和が下限、配信の後の旧いコードの文書の語の記録の書き込み全部の和が上限（ふつうは同じ）。
- A の初めの値は、旧いタブが 4 段で答える前（3 段の後）の A の領域（B に替わった後は A の控え、B にログインしない回は A の localStorage）。
- 1 回目に戻った後の A の領域の語の記録 − A の初めの値が [下限, 上限] に入り、最後に答えた時刻が旧いタブの書いた時刻より前でないこと。足りなければ NOT_IMPORTED（A の値を旧いタブの値で置き換えた形は「置き換えた」と書く）、多ければ DOUBLE。
- 送信待ち: 戻った後に A の送る語の印にその語が入った（見張りの知らせか節目の読み）か、A の名前の送信にその語が A の値で載った。A のクラウドの行（戻って送り切った後）が A の領域と同じ回数。どちらかが無ければ NOT_IMPORTED。
- 学習状況の画面: 3 つの札の語数が、その時の A の語の記録の 3 状態（公開の語だけ・`ls` の 1 と 2）の数と同じ。違えば NOT_IMPORTED。語ごとの 3 状態（初め → 1 回目 → 2 回目）は値を出す。取り込んだ語の 3 状態の決まりは取り込みの仕様しだいなので、`--import-state` で統合担当が決める（`report` 既定 = 出すだけ・`keep` = A の初めの状態のまま・ファイル = 関数）。決まりと違えば NOT_IMPORTED。A の初めの控えに 3 状態の欄が 1 語も無い（移行の前の写し。`--order direct-link` の A の控え）ときは初めの状態が分からないので `keep` は当てない（関数には `priorStates` を渡す）。
- 2 回目に戻った後も 1 回目と同じ値（増えたら DOUBLE。A のクラウドの行も、2 回目の後に増えたら DOUBLE）。1 回目に足りず 2 回目に入った物は NOT_IMPORTED のまま「2 回目に入った」と書く。

「5 段を通ったか」（通らなければ PASS と言わず INVALID・終わりの値 2）:
- 途中で落ちずに 5 段の終わりまで走った（落ちた回は、漏れを見つけていても INVALID。見つけた漏れは記録と終わりの値 1 に残る）
- 旧いタブで A がログインして同期した／旧いタブは旧い木の同期と認証のコードを読んだ／新しいタブは新しい木を受けた／新しいタブで B のセッションが動いた（期限内の B のトークンで受け口が受けた要求がある）
- 見えたままの旧いタブの更新を受け口が止め、新しいタブの移行の後に通した（移行のある木）
- old-frozen は 2・3 段のあいだ凍っていた（同じ文書の検査の時計が止まり・読み直されず・受け口への要求もページの取得も 0。`--freeze off` の回は「試していない」と出す）
- old-offline は 2・3 段のあいだ受け口に届かず、読み直されなかった
- 凍った・通信の切れた・見えたままのタブは最後まで旧いコードのまま
- 旧いコードのまま残ったタブで動いた同期の関数は旧い木の `js/sync.js` の字のまま
- 旧いコードのまま残った `old-live` と `old-frozen` のどれもが、旧い画面で答え、答えのたびにそのタブの中で語の記録を書いた（タブごと・答えごと。片方だけの答えで通さない）。答えに数えるのは、打った後に画面が次の語へ進んだ（訳が替わった）物だけ。そのタブの配信の前の文書の書き込みだけを数え、答えの窓（打ち始めてから、次の語に替わって落ち着いた時 + 0.3 秒まで。ただし同じタブの次の答えの打ち始めで切る）に、答えた語か、答えた後に画面に出た次の語の記録の変化があること。旧いコードは、端末の語の記録にその語が無いと答えた語の記録を書かず（0507672 の `recordCorrect` は記録の無い語で何もしない）、次の語を出す時の記録（`recordPlay`）だけを書く。分離の入った木では移行の後の旧い場所が空なのでこちら、分離の前の木では答えた語そのものが書かれる。書き込みが見えなければ、端末の語の記録が変わっていても通さない。書き込みの記録の無い古い記録（包みの印が無い）だけは、前の決まり（答えた後に端末の語の記録が変わった）で見る
- orphans のある木: 4 段より後に旧いコードのタブが旧い場所へ書いた語の記録が、片付けで orphans に届いたか（値の digest か、書いた語の回数）。届いた数・タブごとの最後の書き込みが届いたか・届かない語は summary の `orphans` に出す。1 つも届かない・orphans を読めない（DB か置き場が無い）・答えを数えたタブ（旧いコードのまま 4 段より後に語の記録を書いた old-live・old-frozen）のどれかの最後の書き込みが届かない（値の digest も、その書き込みで変わった語の回数も写しに無い）ときは通さない
- 旧いコードのタブは読み込み済みのモジュールの呼び出しを誤りなく終えた／見える状態の切り替えに失敗が無い
- 旧いコードのタブのトークンの更新（B のログインの後。`--login none` は書き戻しの後）: 試みた、または試みられない理由を確かめた（どの旧いコードのタブも getSession が空で、旧い認証の鍵が空）
- 旧いタブが答えた後と、旧いタブを閉じた後に、新しいコードの文書を開き直した（新しい文書・落ち着いた・切り替えの画面のある木は /switch.html も読んだ）
- `--login none` の回は「B のセッションが動いた」を試していない（notExercised）
- `--expect-writeback` の回は、止めていた更新を通した後に古い部品が A のセッションを旧い鍵へ書き戻した（書き込みの知らせ）
- A へ戻る段のある回: A へ戻った（領域の印が A・A の取り込みの読みが受け口に届いた）／A から離れてもう一度戻った／学習状況の画面の札を 2 回とも読めた／A の初めの値と戻った後の値を読めた／見張りのタブが最後まで同じ文書で知らせを聞いた／取り込む物がある（数えた答えの書き込みで回数が増えた語があり、書く前の値が分かる）

判定だけの確かめ（ブラウザなし・数秒）: `node tests/oldtab/test-analyze.mjs`（作った記録で、値の規則・表・旧いコードのタブの決まり・落ちた回の判定を見る）。

## 流し方
```
flock <ロック> env CHROME_PATH=<ブラウザ> node tests/oldtab/run.mjs --old 0507672
node tests/oldtab/run.mjs --old 0507672 --new /path/to/other/worktree   # か --new <commit>
node tests/oldtab/run.mjs --old 0507672 --sw off --login link
node tests/oldtab/run.mjs --old 0507672 --mutant mirror-session --expect-leak
node tests/oldtab/run.mjs --old 0507672 --mutant person-key-as-device --sw off --login logout --expect-leak
node tests/oldtab/run.mjs --old 0507672 --mutant orphan-into-area --sw off --login logout --expect-leak
node tests/oldtab/run.mjs --old 0507672 --order direct-link --release login --sw off --old-auth-lib 2.105.0 --expect-writeback
node tests/oldtab/run.mjs --old 0507672 --login none --sw off --old-auth-lib 2.105.0 --expect-writeback
node tests/oldtab/run.mjs --old 0507672 --mutant proto-import --sw off --login logout              # 試作の取り込み（A へ戻る段が通るか）
node tests/oldtab/run.mjs --old 0507672 --import-state keep                                       # 取り込んだ語の 3 状態の決まりを当てる
node tests/oldtab/lib/authLib.mjs           # 認証の部品（固定の版）を置き場に用意するだけ
node tests/oldtab/lib/authLib.mjs --check   # 登録所から取り直して作り、固定の値（と置き場の写し）と同じか確かめる
```
- 既定は Service Worker あり・なし × ログインの 2 通り = 4 回（1 回 3〜4 分）。
- 判定: LEAK（漏れ）・LOSS（漏れは無いが A の記録の後退）・DOUBLE・NOT_IMPORTED（A へ戻る段の取り込み）・PASS・INVALID（段を通れなかった）。
- 終わりの値: 0 = 漏れも後退も無く取り込みも合う・1 = 漏れか後退あり・3 = 取り込みが足りないか 2 度（NOT_IMPORTED・DOUBLE）・2 = 段を通れなかった回がある（処理されない失敗で止まったときも 2。それまでの記録を書く）。1 > 3 > 2 の順に強い。
- `--no-return`: A へ戻る段を流さない（前の 5 段だけ。比べるため）。orphans の無い木（分離の前）には、もともと戻る段が無い。`--expect-leak` は変異の確かめ用（どの回も LEAK なら 0。途中で落ちた回は数えない）。
- `--freeze off`: old-frozen を凍らせない回（凍結の代わりのスクリプトの停止が結果を変えていないかを比べる）。
- 配信の後にサーバーへの要求が 60 秒以上止まると注意を出す（新しい木の Service Worker が有効になるまで、どのタブの取得も待たされた疑い。summary の `longestServerGapSec`）。
- 記録: `--out`（既定は一時置き場の `spelldash-oldtab/logs`）に回ごとの JSON（全部の要求・表の最後の中身・見つけた漏れ・旧いタブの行方・時刻の流れ・使った認証の部品の版と integrity）と summary。

## 認証の部品の取り方（`lib/authLib.mjs`）
本物の部品の配布物の原文（ほかの名前を含む）はリポジトリに置かない。検査の時に取って作り、手元の置き場に置く。
- 固定の版: 2.118.0（両方の木が読む）と 2.105.0（古い部品の回）。版ごとに、登録所の integrity（tarball の sha512）と、作った物の sha256 を `lib/authLib.mjs` に固定している。
- 取り方: 登録所（既定は `lib/authLib.mjs` の `REGISTRY`。env `OLDTAB_REGISTRY` で替えられる）の版の情報を読み、integrity が固定の値と同じか確かめる。tarball を取り、sha512 が版の情報の integrity と同じか確かめる。tarball はメモリの中で開き（ファイルに展開しない）、`package/dist/umd/supabase.js` に export の行を足してブラウザ用のモジュールにする。作った物の注記の後ろ（束と export の行）の sha256 が固定の値と同じか確かめる。
- 前に作業のブランチに置いていた写し（2.118.0）と同じ物: 注記の後ろは 1 バイトも違わない（固定の値は、その写しの注記の後ろの sha256）。注記の文だけが違う。2.105.0 も、前の作り方で手元に作って流していた物と注記の後ろが同じ。
- 置き場: 既定 `tests/oldtab/.cache/auth-lib/`（.gitignore 済み。env `OLDTAB_LIB_CACHE` で替えられる）。モジュール・配布物の LICENSE の文（あれば）・取った時の記録（integrity と sha256）を置く。次からは置き場の写しを確かめて使う（注記の後ろの sha256 が固定の値と同じで、ファイルの全部が、固定の値から作り直した注記の 3 行と注記の後ろと 1 バイトも違わないこと。違えば使わずに作り直す）。登録所に届かなくても、置き場に正しい写しがあれば流せる。
- `--check`: 置き場を使わずに登録所から取り直して作り、固定の値と同じか確かめる。置き場に写しがあれば、取り直した物と 1 バイトも違わないかも確かめる。置き場には書かない。終わりの値 0 = 同じ・1 = 違う（取れなかったときも 1）。
- `--old-auth-lib` には版（`2.105.0`）かファイルを渡す。固定の版でない版も渡せるが、登録所の integrity だけで確かめる（注意を出す）。版を足すときは、`node tests/oldtab/lib/authLib.mjs --version <版>` が出す integrity と sha256 を `PINNED` に足す。
- CI: ジョブ `oldtab` は置き場を控え（cache）に残し、毎回 `--check` で取り直した物と比べてから流す。

## 変異（`lib/mutants.mjs`）
新しい木の写しに当てる。検査が落ちることを見るためと、守りの形を本物の旧いコードに先に当てて見るため（製品の実装ではない）。
- `mirror-session`: 新しいコードが別の鍵に置いたセッションを旧い鍵へ写し、知らせを旧い名前にも流す（認証の世代の分離を破る）。
- `person-key-as-device`: `js/areaGuard.js` の端末の鍵の一覧に人の記録の鍵 `spelldash_streak` を足す（記録の領域の分離を破る。A の連続日数が B の領域からも読める）。`js/areaGuard.js` の無い木では何も変えない。
- `orphan-into-area`: `js/areaSwitch.js` の旧い場所の片付け（`sweepOrphans`）で、移行の後に旧いタブが旧い鍵へ書いた値を、orphans へ写すのに加えて今の領域の鍵へも書く（A の旧いタブの答えが B の領域に入り、開き直した新しいコードが B として送る）。4 段の後と閉じた後の開き直しが無いと見つからない。`js/areaSwitch.js` の無い木では何も変えない。形が変わって当てられなければ止まる。
- `proto-defence`・`proto-no-authkey`・`proto-no-recordkey`: 試作の守り（人の記録の鍵と認証の鍵の世代分け）と、その片方を外した物。
- `proto-import`: 試作の取り込み（A へ戻る段が通ることを見る。製品の実装ではない）。`js/areaSwitch.js` の切り替えで、切り替え先が移行で決めた領域（`sd2.migrated` の area）のとき、まだ取り込んでいない orphans の記録（area の無い物）の語の記録を、語ごとに回数を足して（最後に答えた時刻は新しい方）切り替え先へ入れ、送る語の印に足し、取り込んだ記録の id を `sd2.oldtab-imported` に残す。
- `proto-import-every`（取り込んだ記録を覚えない → DOUBLE のはず）・`proto-import-replace`（回数を足さずに旧いタブの値で置き換える → NOT_IMPORTED のはず）。

## 確かめられないこと
- 実機の端末（携帯の端末のブラウザ）の凍結・戻るの控え・裏のタブの間引き。ここは画面の無いブラウザと、開発用の口の凍結だけ。
- 本番の受け口の振る舞いのうち、にせの受け口が持たない物（行の権限の細かい規則・トークンの使い回しの猶予の正確な長さ・メールの送信）。
- 旧いタブの見える状態の切り替えは、ブラウザの代わりに `document.visibilityState` を上書きして `visibilitychange` を投げる（画面の無いブラウザではタブはどれも見えるまま）。
- 凍結はスクリプトを止めて代える（本物の凍結より強い: 凍結しない種類の仕事も止まる）。
- 読み直しの届かないタブは、サーバーの 204 で代える（本番で読み直しが届かない理由（凍結・裏・通信断）そのものではない）。
- 認証の部品の版: 両方の木が読むのは 2.118.0（今、本番の読み先が `@2` で返す版）。本番の旧いタブは、開いた時に本番の読み先が `@2` で返した版を持つ（2.118.0 より前のこともある）。2.118.0 は更新の途中で保存が変わると結果を捨てる（`AuthRefreshDiscardedError`。この守りは 2.107.0 から）。それより前の版は `--old-auth-lib <版>` で旧いタブにだけ読ませる（流したのは 2.105.0 だけ。固定の値を持つ古い版も 2.105.0 だけ）。書き戻された A のセッションで旧いタブは A として動ける（B にはならない）が、移行の後の空の端末の値を A のクラウドへ送りうる（判定 LOSS で見る）。
